# 알림 명세

- 상태: 검토용 초안 v0.1 / 작성일: 2026-11-04 / 대상: MVP2

## 1. 목적과 범위

사용자는 알림 설정 하나로 날씨 알림과 배달 할인 알림을 함께 받거나 끈다. 배달 할인 알림은 `delivery_discount_offers`에 저장된 배민·쿠팡이츠 할인정보를 기준으로 정해진 시각에 발송한다.

공통 알림 수신 설정, FCM 기기 등록, 배달 할인 알림의 발송 조건·문구·스케줄을 다룬다. 생활 날씨 알림의 분석·발송 정책은 [날씨 명세](weather.md#33-알림), 배달 할인 데이터와 화면은 [저렴한 한 끼 명세](cheap-meals.md#34-배달)를 따른다. 모바일의 OS 알림 권한과 FCM 토큰 획득은 범위에 포함하지 않는다. 알림 설정 화면은 마이의 생활 날씨 카드에 있는 **알림 받기** 토글이다([생활 날씨 카드 문서](../../../frontend/docs/weather-ui-prototype.md)).

다음은 이번 범위에서 제외하고 알림 시스템 고도화 때 다룬다.

- 광고성 정보 표기(`(광고)`, 수신 거부 안내)와 야간 수신 동의
- 중복 발송 방지·멱등성, 발송 실패 재시도
- 메시지 큐·비동기 발송, 발송 지연 측정과 대량 발송 부하 테스트
- 알림 유형별 개별 수신 설정

## 2. 요구사항

- `REQ-NOTIFICATION-001`: 회원은 공통 알림 수신 동의 하나로 날씨 알림과 배달 할인 알림을 함께 켜고 끈다.
- `REQ-NOTIFICATION-002`: 회원은 알림을 받을 기기 하나를 등록·해제한다.
- `REQ-NOTIFICATION-003`: 수신에 동의한 회원에게 매일 10·11·18·22시에 조건에 맞는 배달 할인 안내를 보낸다.
- `REQ-NOTIFICATION-004`: 배달 할인 알림을 누르면 저렴한 한 끼의 배달 탭으로 이동한다.

## 3. 정책

### 3.1. 공통 알림 수신 설정

- `POL-NOTIFICATION-001`: 수신 동의는 기본 OFF이며 회원당 하나다. 날씨와 배달 할인 알림이 같은 동의를 참조하고, 유형별 ON/OFF는 제공하지 않는다.
- `POL-NOTIFICATION-002`: 저장된 위치가 없어도 수신 동의를 켤 수 있다. 날씨 알림은 저장된 위치가 있어야 발송하고, 배달 할인 알림은 위치와 무관하게 발송한다. 위치를 확인하지 못한 채 켜면 화면은 날씨를 위치 확인 뒤 알려 준다고 안내하고, 다음에 마이를 열 때 위치를 다시 확인한다.
- `POL-NOTIFICATION-003`: 앱의 OS 알림 권한과 서버의 수신 동의는 따로 관리한다. 서버는 수신 동의가 ON이고 FCM 토큰이 등록된 기기에만 보낸다. OS 권한을 해제하면 앱이 기기 해지를 호출해 토큰을 지운다.
- `POL-NOTIFICATION-004`: 기기 등록·해지, 설치 비밀키 기반 소유 증명, 탈퇴 시 동의 OFF와 토큰 삭제는 기존 날씨 알림 기기 정책을 그대로 따른다. 날씨 알림이 배포 전이라 기존 설정을 이전하지 않고, 기존 테이블 이름만 V11 마이그레이션으로 바꾼다.

| API                                                           | 설명                          |
| ------------------------------------------------------------- | ----------------------------- |
| `GET/PUT /api/members/me/notification-settings`               | 공통 알림 수신 동의 조회·변경 |
| `GET/PUT/DELETE /api/members/me/notification-devices/current` | FCM 기기 조회·등록·해지       |

### 3.2. 배달 할인 알림 발송 조건

- `POL-NOTIFICATION-005`: 모든 시각과 날짜는 한국 시간(`Asia/Seoul`) 기준이다. 서버 시간대와 관계없이 KST 오늘로 유효 기간을 판단한다.
- `POL-NOTIFICATION-006`: 유효한 할인은 `is_active = TRUE`이고 시작일이 없거나 오늘 이전, 종료일이 없거나 오늘 이후인 할인이다. 시작일·종료일 당일을 포함한다.
- `POL-NOTIFICATION-007`: 유효한 할인 중 유형별 조건에 맞는 할인이 하나도 없으면 그 실행은 발송하지 않는다.
- `POL-NOTIFICATION-008`: 선착순 할인은 `conditions`에 `10시 선착순`·`11시 선착순` 문구가 있는 할인으로 판단하며 공백 차이는 무시한다. 운영자는 선착순 할인을 등록할 때 이 문구를 조건에 적는다.
- `POL-NOTIFICATION-009`: 실제 쿠폰 소진 여부는 확인하지 않고 DB에 저장된 날짜와 조건만으로 판단한다.
- `POL-NOTIFICATION-010`: 종료일은 당일까지 유효하므로 다음 날 00:00에 끝나는 것으로 보고, 종료일 당일 22:00에 마감 안내를 보낸다.

| 유형            | 발송 시각 | 발송 조건                               | 제목                           | 내용                                                       |
| --------------- | --------- | --------------------------------------- | ------------------------------ | ---------------------------------------------------------- |
| 배민 선착순     | 10:00     | 배민 할인의 조건에 `10시 선착순`        | 10시 선착순 배달 할인 시작! 🎉 | 수량이 소진되기 전에 할인 혜택을 확인해 보세요!            |
| 쿠팡이츠 선착순 | 11:00     | 쿠팡이츠 할인의 조건에 `11시 선착순`    | 11시 선착순 배달 할인 시작! 🎉 | 수량이 소진되기 전에 할인 혜택을 확인해 보세요!            |
| 저녁 할인 안내  | 18:00     | 유효한 할인이 하나 이상                 | 오늘 하루도 고생 많았어요! 🍗  | 고된 하루, 오늘 저녁은 배달 할인으로 맛있게 즐겨보세요!    |
| 마감 2시간 전   | 22:00     | 종료일이 오늘인 유효한 할인이 하나 이상 | 배달 할인 혜택, 곧 끝나요! ⏰  | 곧 종료되는 할인 혜택이 있어요! 놓치기 전에 확인해 보세요. |

### 3.3. 배달 할인 알림 발송

- `POL-NOTIFICATION-011`: 조건에 맞는 할인이 여러 개여도 실행마다 기기당 안내 하나만 보낸다. 할인 목록이나 브랜드를 본문에 넣지 않는다.
- `POL-NOTIFICATION-012`: 푸시 data의 `url`은 `/cheap-meals?tab=delivery`다. 앱은 현재 서비스 origin 기준의 내부 경로로 열어 배달 탭을 보여준다.
- `POL-NOTIFICATION-013`: 한 기기 발송이 실패해도 다른 기기 발송을 계속한다. 실패를 재시도하지 않고, 실행마다 성공·실패 건수를 로그로 남긴다. 토큰과 외부 예외 본문은 로그에 남기지 않는다.
- `POL-NOTIFICATION-014`: 스케줄러는 `delivery-discount.notification.enabled=true`일 때만 등록되며 모든 환경에서 기본 OFF다. FCM 발송은 `weather.notification.enabled=true`일 때 만들어지는 공통 발송기를 사용한다. 22시 광고성 푸시에 필요한 야간 수신 동의와 광고 표기, 중복 발송 방지를 정하기 전에는 켜지 않는다.
- `POL-NOTIFICATION-016`: 발송 수를 셀 수 있게 기기마다 발송 기록을 `delivery_discount_notifications`에 남긴다. 기록은 푸시 data의 `notificationId`, 회원, 알림 유형, 발송일(KST), 성공 여부, 발송 시각이며 토큰과 본문은 저장하지 않는다. 기록 저장에 실패해도 다음 기기 발송을 계속한다.

### 3.4. 푸시 data

- `POL-NOTIFICATION-015`: 모든 푸시 data에는 `notificationId`와 알림 종류 `type`을 싣는다. `type`은 푸시 클릭부터 목표 행동까지의 퍼널을 알림 종류별로 나누는 기준이므로 값을 바꾸지 않는다. 눌렀을 때 열 화면이 있으면 `url`도 싣는다.

| `type`            | 알림                    |
| ----------------- | ----------------------- |
| `weather`         | 생활 날씨 알림          |
| `delivery_coupon` | 배달 할인 알림          |
| `test`            | 수신 확인용 테스트 알림 |

## 5. 미정 사항

- 실기기 수신과 알림 클릭 이동은 스케줄러를 켜는 환경에서 확인한다. 이번 작업은 테스트 코드로 발송 조건·메시지·스케줄 연결만 검증했다.
- 광고성 정보 표기와 야간(21–08시) 수신 동의 수집 방식, 22시 마감 안내의 유지 여부를 정해야 한다.
- 서버가 여러 대일 때의 중복 발송 방지 방식을 정해야 한다.
