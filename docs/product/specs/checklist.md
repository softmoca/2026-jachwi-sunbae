# 체크리스트 기능 명세

## 1. 목적과 범위

사용자는 제공된 질문으로 양식을 만들고, 특정 매물에 적용해 확인 상태와 항목 메모를 남긴다.

현장(ON_SITE)·계약 전(PRE_CONTRACT) 두 단계를 제공한다.

- **시스템 제공 항목**: 서비스가 관리하는 질문. 같은 질문은 같은 시스템 항목 ID로 식별한다.
- **시스템 기본 체크리스트**: 단계별 활성 CORE로 구성하는 기본 양식.
- **사용자 체크리스트**: 사용자가 선택한 질문과 순서의 양식. CORE도 제거할 수 있다.
- **매물 적용 체크리스트**: 적용 당시 양식을 복사해 특정 매물의 결과를 기록하는 대상. 원본 양식을 삭제해도 기존 기록은 유지한다. 원본 양식을 수정하면 그 양식을 적용한 매물마다 다시 적용해 바뀐 질문을 보여 주고, 같은 질문의 결과와 메모는 승계한다 (`REQ-CHECK-011`).
- **진행 현황**: 해당 매물의 체크 상태를 집계한 결과.

## 2. 요구사항

- `REQ-CHECK-001`: 현장·계약 전 두 단계로 질문과 양식을 구분한다.
- `REQ-CHECK-002`: 제공 항목을 CORE·OPTIONAL로 구분하고 신규 선택에서는 활성 항목을 제공한다.
- `REQ-CHECK-003`: 검색어로 제공 항목을 찾아 양식에 추가한다.
- `REQ-CHECK-004`: 자신의 사용자 체크리스트를 생성·조회·수정·논리 삭제한다.
- `REQ-CHECK-005`: 생성 화면에 활성 CORE를 초기 구성으로 제공하고 선택 항목을 추가할 수 있게 한다.
- `REQ-CHECK-006`: 이름·항목 포함 여부·전체 순서를 변경해 저장한다.
- `REQ-CHECK-007`: 생성·수정 단계에서 CORE도 제거할 수 있다.
- `REQ-CHECK-008`: 매물에 시스템 기본 또는 자신의 사용자 체크리스트를 선택해 적용·교체한다.
- `REQ-CHECK-009`: 기본 체크리스트를 적용하면 해당 단계의 활성 CORE를 매물 기록으로 복사한다.
- `REQ-CHECK-010`: 사용자 양식을 적용하면 이름·단계·질문·시스템 항목 ID·순서를 매물 전용 기록으로 복사한다.
- `REQ-CHECK-011`: 양식 교체 시 공통 질문의 결과를 승계하고 신규·제외 질문을 구분한다.
- `REQ-CHECK-012`: 매물 생성 시 회원·단계별 최근 적용 양식 또는 기본 양식을 자동 적용한다.
- `REQ-PROGRESS-001`: 각 항목의 상태는 미확인·괜찮음·주의다.
- `REQ-PROGRESS-002`: 신규 매물의 항목은 미확인과 빈 항목 메모로 시작한다.
- `REQ-PROGRESS-003`: 상태와 항목 메모를 서로 독립적으로 저장한다. 상태는 선택 즉시, 메모는 저장 버튼으로 저장한다.
- `REQ-PROGRESS-004`: 전체·완료·괜찮음·주의·미확인 수를 제공한다.
- `REQ-PROGRESS-005`: 매물 상세에 현장 체크리스트 집계를 보여준다.
- `REQ-PROGRESS-006`: 매물 목록에서도 현장 체크리스트 집계를 보여준다.

## 3. 정책

### 3.1. 사용자 양식과 제공 항목

- `POL-CHECK-001`: 서비스가 제공 질문을 수정하거나 제공을 중단해도, 이미 매물에 저장된 질문·체크 상태·메모는 자동으로 변경하지 않는다. 기존에 적용된 기록은 유지된다.
- `POL-CHECK-002`: 사용자 양식을 논리 삭제하면 조회·수정·신규 적용에서 제외한다. 이미 매물에 적용한 기록은 유지한다.
- `POL-CHECK-003`: 사용자는 질문을 직접 새로 작성하지 않고 시스템 제공 항목에서 선택한다.
- `POL-CHECK-004`: 질문의 문장 형태와 관계없이 두 단계 모두 미확인·괜찮음·주의를 사용한다.
- `POL-CHECK-005`: 이름은 1~~30자, 항목은 1~~30개로 제한한다. 전체 순서는 사용자가 정한다.

### 3.2. 최초 자동 적용과 최근 선택

- `POL-CHECK-006`: 새 매물의 현장·계약 전 단계에 각각 양식을 자동 적용한다. 해당 회원이 그 단계에 마지막으로 적용 완료한 양식을 사용한다.
- `POL-CHECK-007`: 최근 적용 이력이 없거나 대상 양식이 삭제되면 단계별 시스템 기본 양식을 사용한다. 기본 양식으로 교체한 경우 최근 선택도 기본으로 기록한다.
- `POL-CHECK-008`: 최근 적용 선택은 회원·단계별로 분리한다. 양식 조회·생성·수정만으로 바뀌지 않으며, 홈의 매물 정렬과 관계없다.

### 3.3. 같은 매물에서 양식 교체

- `POL-CHECK-009`: 기존 상태·항목 메모를 유지하고 새 양식의 질문·순서로 구성한다. (이전·새 양식에 같은 시스템 항목 ID가 있음)
- `POL-CHECK-010`: 미확인·빈 메모로 시작한다. (새 양식에만 있음)

### 3.4. 상태·항목 메모·진행 현황

- `POL-PROGRESS-001`: GOOD·CAUTION은 확인 완료이며 UNCONFIRMED는 미확인이다.
- `POL-PROGRESS-002`: 진행률은 floor(완료 항목 수 ÷ 전체 항목 수 × 100), 전체 0개이면 0이다.
- `POL-PROGRESS-003`: 항목 메모는 최대 500자이다.

| AC-CHECK-006 | 원본 양식의 이름·질문 구성·순서를 수정하거나 양식을 삭제한다.             | 이미 매물에 적용한 질문·순서·상태·메모가 바뀌지 않는다.                                                |
| AC-CHECK-007 | 한 단계의 3항목에 괜찮음·주의·미확인을 하나씩 저장한다.                   | 완료 2·전체 3·각 상태 1, 진행률 66%를 표시한다.                                                        |
| AC-CHECK-008 | 현재 [A,B] 중 B에 주의·누수 확인을 저장한 뒤 [B,C]로 교체한다.            | B 결과는 유지, C는 미확인·빈 메모, A는 현재 집계·새 PDF에서 제외된다. A의 기록을 물리 삭제하지 않는다. |

`AC-CHECK-008`- **한매물에 적용 중인 체크리스트 양식을 교체했을 때, 기존 기록을 어떻게 처리할지**

**A·B·C는 각각 체크리스트의 질문 항목**을 뜻함

- **A:** 수압은 괜찮은가?
- **B:** 누수 흔적은 없는가?
- **C:** 방음은 괜찮은가?

현재 매물에 적용한 양식은 [A, B]이고, B에 다음 기록을 저장했다고 가정.

> 체크 상태: **주의**
>
> 항목 메모: **누수 확인**

이제 같은 매물에서 양식을 [B, C]로 교체하면 다음 결과를 기대함.

| 항목        | 교체 후 처리                       | 이유                                    |
| ----------- | ---------------------------------- | --------------------------------------- |
| **A: 수압** | 현재 체크리스트에서 빠짐           | 새 양식에 없는 질문이기 때문            |
| **B: 누수** | **주의 / 누수 확인**을 그대로 유지 | 두 양식에 공통으로 포함된 질문이기 때문 |
| **C: 방음** | **미확인 / 빈 메모**로 시작        | 새로 들어온 질문이기 때문               |

## 5. 미정 사항

현재 미정 사항은 없다.

## 6. 제공 질문 목록 변경안 (V13)

V13에서 현장(`ON_SITE`) 제공 항목을 아래 CORE 12개·OPTIONAL 10개로 교체하고, 계약 전(`PRE_CONTRACT`) 항목은 제공을 중단한다.
기존 항목은 논리 삭제하고 새 항목은 새 ID로 등록한다. 기존 사용자 양식과 매물의 질문·상태·메모·최근 선택은 변경하지 않는다.
기존 매물에서 새 기본 양식으로 교체할 때 새 ID인 항목은 미확인·빈 메모로 시작한다.

이번 변경은 SQL과 제공 목록 명세만 준비한다. 위 요구사항에 남아 있는 계약 전 단계의 API·자동 적용·화면 제거는 후속 코드 변경에서 처리한다.
현재 코드는 현장·계약 전 두 단계의 기본 양식을 자동 적용하므로, V13을 단독 배포하면 계약 전 기본 목록이 비게 된다. 후속 코드 변경과 함께 배포해야 한다.

### 카테고리

`system_check_items`에 `category VARCHAR(30) NOT NULL DEFAULT 'OTHER'` 컬럼 하나를 추가한다.
카테고리는 질문 주제이며 기본 제공 여부인 CORE·OPTIONAL과 독립적이다.
사용자 양식·매물 기록 테이블에는 컬럼을 추가하지 않는다. 기존 항목의 카테고리는 `OTHER`로 유지한다.
API 응답과 UI에서의 카테고리 사용은 후속 코드 변경에서 반영한다.

| 코드             | 표시명      |
| ---------------- | ----------- |
| `SECURITY`       | 보안        |
| `WINDOW_LIGHT`   | 창문·채광   |
| `WATER_BATHROOM` | 수도·화장실 |
| `ROOM_CONDITION` | 방 상태     |
| `BASIC_OPTIONS`  | 기본 옵션   |
| `OTHER`          | 기타        |

### CORE — 기본 제공 12개

#### 보안

- 현관문 잠금장치 잘 작동하는지
- 공동 현관 출입 통제되는지

#### 창문·채광

- 햇빛 잘 들어오는지
- 창문·방충망 상태 괜찮은지

#### 수도·화장실

- 싱크대·샤워기 물 잘 나오는지
- 온수 잘 나오는지
- 배수구·변기 물 잘 내려가는지

#### 방 상태

- 벽지·창틀에 곰팡이 있는지
- 천장·벽에 물 얼룩 있는지
- 외부 소음 심하지 않은지

#### 기본 옵션

- 에어컨·냉장고 작동하는지
- 옵션·수납공간 충분한지

### OPTIONAL — 필요에 따라 추가할 10개

#### 보안

- 방충망·방범창 상태 괜찮은지

#### 수도·화장실

- 샤워 공간 충분한지

#### 방 상태

- 콘센트 위치·개수 충분한지
- 휴대전화 신호 잘 잡히는지
- 인터넷 설치·이용 가능한지

#### 기본 옵션

- 가구 배치·수납공간 충분한지
- 세탁기·냉장고 정상 작동하는지

#### 기타

- 복도·계단·엘리베이터 관리 상태 괜찮은지
- 주차·자전거 보관 공간 있는지
- 쓰레기 배출·분리수거 방법 확인했는지

### 계약 전 단계와 공통 컬럼

`PRE_CONTRACT`는 별도 컬럼이 아니라 `stage` 컬럼의 값이다. `stage`는 현장 항목·사용자 양식·매물 기록·최근 선택에서도 공유한다.
이번 V13에서는 계약 전 제공 항목만 비활성화하고 공통 `stage` 컬럼과 제약조건은 유지한다.
