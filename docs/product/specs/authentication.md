# 회원·인증 기능 명세

- 상태: 익명 인증 유지·OAuth 계정 연결 정책 / 수정일: 2026-11-03 / 대상: MVP1-2
- 관련 이슈: [#523](https://github.com/woowacourse-teams/2026-jachwi-sunbae/issues/523). OAuth 연결·기록 통합·다중 인증 세션·로그아웃은 이번에 구현할 목표 정책이며, 현재 구현 완료를 의미하지 않는다.

## 1. 목적과 범위

사용자는 로그인 정보를 입력하지 않고 서비스를 시작해 자신의 매물과 체크 기록을 저장·조회한다. PostHog에서 기존 로그인 화면 방문자의 85%가 이탈한 것을 확인해 입력 화면을 제거한다.

첫 방문에는 익명 회원을 만들고, 이후에는 브라우저·앱이 보관한 Refresh Token으로 같은 회원을 식별한다. 익명 회원은 자신의 실제 기록을 사용하며, 별도의 게스트 샘플 데이터 조회는 제공하지 않는다. 회원 ID는 사람이나 기기의 고유 ID를 뜻하지 않는다.

사용자는 필요할 때 카카오·Apple 계정을 연결해 기록을 보관하고, 다른 기기에서도 같은 OAuth 계정으로 기존 기록을 이어 쓴다. 이미 OAuth에 연결된 회원이 있으면 현재 익명 기록을 그 회원에게 통합하고, 이후 기록도 해당 회원에 저장한다. 서로 다른 OAuth 계정의 기록 이전·병합, 여러 로그인 수단을 한 회원에 추가하는 기능, 기존 닉네임 회원의 기록 전환은 이번 범위에서 제외한다. 현재 웹·WebView 인증을 확장하며 네이티브 앱이 업무 API를 직접 호출하는 구조로의 전환은 포함하지 않는다.

## 2. 요구사항

- `REQ-AUTH-001`: 앱을 시작할 때 입력 없이 인증을 시작한다. 회원이 없으면 익명 회원을 자동 생성한다.
- `REQ-AUTH-002`: 유효한 Refresh Token을 보관한 환경에서는 재방문해도 같은 회원의 기록을 이용한다.
- `REQ-AUTH-003`: Access Token이 만료되면 화면 상태를 유지한 채 새 토큰을 발급받아 이용을 계속한다.
- `REQ-AUTH-004`: 로그인 요청에서 기존 인증을 복원할 수 없으면 새 익명 회원으로 시작한다. 이전 회원의 데이터는 이 요청으로 삭제하지 않는다.
- `REQ-AUTH-005`: 토큰 갱신 요청에서 기존 인증을 복원할 수 없으면 실패를 알리고 새 회원을 자동 생성하지 않는다.
- `REQ-AUTH-006`: 인증 시작·복원·토큰 갱신·OAuth 인증 처리와 구분되는 업무 API는 익명 회원에게도 Access Token을 요구한다.
- `REQ-AUTH-007`: 회원은 다른 회원의 매물·체크 기록을 조회·변경·삭제할 수 없다.
- `REQ-AUTH-008`: DB 장애나 저장 데이터 손상을 인증 실패 또는 새 회원 생성으로 숨기지 않는다.
- `REQ-AUTH-009`: 회원은 탈퇴할 수 있다. 탈퇴하면 소유 기록을 논리 삭제하고 인증 정보를 폐기한다.

마이 화면의 초기화와 메일 삭제 요청은 다음을 따른다.

- `REQ-AUTH-010`: 회원은 마이 화면의 초기화로 지금 회원을 탈퇴 처리하고 새 익명 회원으로 다시 시작할 수 있다. 이전 회원의 기록에는 더 이상 접근할 수 없다.
- `REQ-AUTH-011`: 계정과 데이터를 완전히 지우는 것은 메일 요청으로 받는다. 요청하면 초기화 전 이전 회원의 데이터까지 파기한다.

OAuth 연결과 기기 간 기록 이용은 다음을 따른다.

- `REQ-AUTH-012`: OAuth 연결 없이도 기존처럼 익명으로 이용하며, 사용자가 선택할 때 카카오·Apple 계정을 연결한다.
- `REQ-AUTH-013`: 처음 연결하는 OAuth 계정이면 현재 익명 회원의 ID와 기록을 유지한다. 이미 연결된 회원이 있으면 그 회원으로 익명 기록을 통합한다.
- `REQ-AUTH-014`: 같은 OAuth 계정을 사용하는 여러 기기는 같은 회원의 기록을 이용하되 서로 다른 인증 세션을 가진다.
- `REQ-AUTH-015`: 서로 다른 OAuth 계정은 별도 회원으로 관리하며, 계정 전환으로 기록을 자동 통합하지 않는다.
- `REQ-AUTH-016`: 회원은 현재 기기에서 로그아웃하고 새 익명 회원으로 시작할 수 있다. 기존 OAuth 연결과 기록은 유지하며 같은 OAuth로 다시 로그인하면 복원한다.
- `REQ-AUTH-017`: OAuth 인증을 취소하거나 검증·통합에 실패하면 기존 회원과 기록을 유지하고, 실패를 새 회원 생성으로 숨기지 않는다.

## 3. 정책

### 3.1. 익명 회원과 기록

- `POL-AUTH-001`: 첫 `POST /api/auth/login` 요청에 Refresh Token이 없으면 새 회원 ID를 생성한다. 닉네임·비밀번호 입력이나 기기 식별값은 사용하지 않는다.
- `POL-AUTH-002`: 유효한 Refresh Token이 정상 회원과 연결돼 있으면 같은 회원을 복원한다. 탈퇴한 회원은 복원하지 않는다.
- `POL-AUTH-003`: 로그인 요청의 Refresh Token이 없거나 만료·삭제됐거나 정상 회원과 연결되지 않으면 새 익명 회원을 생성한다. 기존 회원과 기록은 자동 삭제하지 않으며, OAuth 인증 전에는 새 회원에게 이전 기록을 연결하지 않는다.
- `POL-AUTH-004`: 브라우저 프로필·앱마다 인증 정보를 별도로 보관한다. 익명으로 처음 시작하면 각각 다른 회원이 되지만, 같은 OAuth 계정으로 인증하면 서로 다른 토큰으로 같은 회원을 이용할 수 있다.
- `POL-AUTH-005`: 회원 소유 데이터는 인증된 회원 ID를 기준으로 조회·변경·삭제 권한을 확인한다. 다른 회원의 자원은 `404`로 응답하고 노출하지 않는다.

### 3.2. 토큰과 API 접근

- `POL-AUTH-006`: Access Token은 15분간 유효한 JWT다. 인증 시작·복원·토큰 갱신·OAuth 인증 처리와 구분되는 모든 업무 API 요청에 `Authorization: Bearer <Access Token>` 헤더로 전달한다. 지도·검색 조회에도 적용하며 익명·OAuth 회원 모두 같은 방식을 사용한다.
- `POL-AUTH-007`: Refresh Token은 365일간 유효하며 웹·현재 WebView 앱에는 HttpOnly·Secure 쿠키로 전달한다. 서버에는 원문 대신 해시를 저장한다.
- `POL-AUTH-008`: 유효한 Refresh Token으로 일반 인증을 복원하거나 토큰을 갱신하면 토큰 값은 유지하고 만료 시각을 그때부터 365일로 연장한다. OAuth 인증 완료에 따른 토큰 교체는 별도로 처리한다.
- `POL-AUTH-009`: `POST /api/auth/refresh`는 기존 회원의 Access Token만 재발급한다. Refresh Token이 없거나 유효하지 않으면 `401 REFRESH_TOKEN_INVALID`를 반환하고 새 회원을 생성하지 않는다.
- `POL-AUTH-010`: 업무 API에 Access Token이 없거나 유효하지 않으면 `401 ACCESS_TOKEN_INVALID`를 반환한다. Access Token 만료 후 갱신에 성공하면 원래 요청을 한 번 재시도한다.
- `POL-AUTH-011`: 로그인·토큰 갱신 과정의 DB 조회·저장 장애 또는 저장 데이터 손상은 서버 오류로 처리한다.
- `POL-AUTH-012`: `DELETE /api/members/me`는 회원·매물·사진 메타데이터·사용자 체크리스트·거리 메모를 논리 삭제하고 Refresh Token을 서버에서 삭제한다. 응답에서 Refresh 쿠키를 만료시키며, 기존 Access Token도 회원 상태 검사를 통해 거절한다.
- `POL-AUTH-013`: 탈퇴 시 날씨 알림 설정을 비활성화하고 기기 푸시 토큰을 제거한다. 프론트엔드는 탈퇴 성공 후 메모리의 Access Token과 회원별 캐시를 비운다.

### 3.3. 초기화

- `POL-AUTH-014`: 마이 화면의 초기화는 `DELETE /api/members/me`가 성공하면 메모리의 Access Token을 비우고 `POST /api/auth/login`을 보낸다. Refresh 쿠키가 만료됐으므로 서버는 새 익명 회원을 만들고, 프론트엔드는 새 토큰을 설정한 뒤 React Query 캐시를 비우고 홈으로 이동한다. 탈퇴 요청이 401을 받으면 토큰을 한 번 갱신해 다시 보낸다.
- `POL-AUTH-015`: 탈퇴 요청이 실패하면 기존 회원과 인증 상태, 화면을 그대로 둔다. 탈퇴 뒤 로그인이 실패하면 이전 회원으로 되돌아가지 않고, 다음 요청의 자동 로그인이 새 회원을 만든다.
- `POL-AUTH-016`: 초기화로 논리 삭제된 이전 회원의 기록과 사진 파일은 초기화한 날부터 90일 동안 보관한 뒤 파기한다. 사용자가 앱에서 삭제한 매물, 체크리스트, 거리 메모도 삭제한 날부터 90일 뒤 같은 기준으로 파기한다.
- `POL-AUTH-017`: 메일로 계정과 데이터의 완전 삭제를 요청하면 지금 회원과 초기화 전 이전 회원의 데이터를 함께 파기한다.

### 3.4. OAuth 연결과 계정 전환

- `POL-AUTH-018`: OAuth 계정은 제공자와 검증된 사용자 식별값의 조합으로 구별하고 하나의 서비스 회원에만 연결한다. 회원당 하나의 OAuth 계정을 연결하며 이메일·닉네임으로 동일 회원이라고 추정하지 않는다.
- `POL-AUTH-019`: 현재 익명 회원이 처음 연결하는 OAuth 계정이면 현재 회원에 연결 정보만 추가한다. 별도 회원을 만들거나 기록을 이동하지 않는다. 이미 연결된 회원이 있으면 그 회원을 기준 회원으로 정해 현재 익명 기록을 통합한다.
- `POL-AUTH-020`: OAuth가 연결된 회원이 같은 계정으로 인증하면 같은 회원을 사용한다. 다른 OAuth 계정을 선택하면 기록 통합 없이 해당 계정으로 전환하며, 연결된 회원이 없으면 별도 회원을 생성한다. 서로 다른 카카오 계정 및 카카오·Apple 사이의 기록 이전·병합은 지원하지 않는다.
- `POL-AUTH-021`: 연결 전에 이 기기의 익명 기록이 선택한 OAuth 계정에 저장되며 다른 계정으로 이전하는 기능은 지원하지 않음을 안내한다. 인증 취소·실패 시 현재 회원과 기록을 유지한다.
- `POL-AUTH-022`: 카카오·Apple 인증 결과는 백엔드에서 검증해 우리 회원을 찾는 데 사용한다. 카카오 토큰은 우리 업무 API 인증과 분리하며 클라이언트에 전달하지 않는다. 카카오를 로그인에만 사용하므로 Refresh Token 장기 보관·주기적 갱신은 범위에 포함하지 않는다. 카카오 토큰 만료만으로 저장된 계정 연결이나 우리 인증을 종료하지 않는다.

### 3.5. 익명 기록 통합

- `POL-AUTH-023`: 익명 회원의 매물·사진 메타데이터·사용자 체크리스트·거리 메모와 관련 기록은 기준 회원으로 소유권을 이전한다. 이름·주소·위치가 같아도 중복 제거하거나 내용을 덮어쓰지 않는다. 기존 ID·내용·삭제 상태와 기록 간 연결을 보존한다.
- `POL-AUTH-024`: 날씨 위치·알림 설정 등 회원당 하나인 값은 이미 OAuth에 연결된 기준 회원의 설정을 유지한다. 생성일이 더 빠른 회원을 고르는 것은 아니다. 기준 회원에 해당 설정이 아예 없을 때만 익명 회원의 값을 가져오며, 알림 끄기 등 명시적으로 설정한 값은 덮어쓰지 않는다.
- `POL-AUTH-025`: 기록 이전·설정 반영·원래 익명 회원 비활성화·인증 전환은 한 트랜잭션으로 처리하고, 반복·동시 요청으로 중복 통합하지 않는다. 원래 익명 회원의 모든 Refresh Token을 폐기하고 기존 Access Token도 회원 상태 검사로 거절한다. 이전한 기록을 삭제하는 탈퇴·초기화 처리로 통합을 대신하지 않는다.
- `POL-AUTH-026`: 서버는 현재 익명 회원의 인증과 기준 회원을 확인한 OAuth 인증 결과를 모두 확인한다. 클라이언트가 전달한 회원 ID만으로 통합하지 않으며 OAuth 시작 요청과 완료 결과를 안전하게 연결한다.

### 3.6. 기기별 인증과 보관

- `POL-AUTH-027`: 익명·OAuth 회원에 같은 토큰 인증 구조를 사용한다. 한 회원에 여러 Refresh Token을 허용하며, 브라우저 프로필·앱 설치별로 독립된 토큰을 발급한다. 기기 고유 ID는 사용하지 않는다.
- `POL-AUTH-028`: OAuth 인증 완료 시 현재 기기의 기존 Refresh Token을 폐기하고, 선택된 회원의 Access Token과 새로운 Refresh Token을 발급한다. 통합 전 익명 토큰을 기준 회원에게 재연결해 재사용하지 않는다. 기준 회원이 다른 기기에서 사용하던 인증은 유지한다.
- `POL-AUTH-029`: 프론트엔드는 회원 전환 후 이전 Access Token과 회원별 캐시를 비우고 새 인증·기록을 적용한다. 다른 탭에도 회원 전환을 알리고 이전 회원으로 요청한 늦은 응답을 새 회원 화면에 반영하지 않는다.
- `POL-AUTH-030`: 웹과 현재 WebView 앱은 Access Token을 웹 메모리에, Refresh Token을 각 환경의 HttpOnly·Secure 쿠키에 보관한다. 앱의 OAuth 인증은 시스템 브라우저나 제공자 SDK를 이용한다. 외부 브라우저와 WebView의 쿠키 공유를 가정하지 않고 완료 결과를 WebView 인증으로 연결한다. 일회용 완료 코드를 사용하는 경우 인증 요청에 연결하고, 짧은 유효기간과 일회 사용을 보장한다.

### 3.7. 로그아웃과 외부 계정 연결 해제

- `POL-AUTH-031`: 로그아웃은 현재 기기의 인증 세션만 폐기하고 Refresh 쿠키·메모리 Access Token·회원별 캐시를 비운 뒤 새 익명 회원으로 시작한다. 기존 OAuth 연결·기록과 다른 기기의 인증은 유지한다. 같은 OAuth로 다시 인증하면 기존 회원을 복원하고 새 익명 기록이 있으면 통합한다.
- `POL-AUTH-032`: 초기화·탈퇴는 기존 회원과 기록을 삭제하는 동작이며 로그아웃과 구분해 안내한다. OAuth 회원 탈퇴 시 모든 인증 세션 폐기와 외부 계정 연결 해제를 함께 처리한다. 제품 기록은 기존 삭제 정책을 따르되 OAuth 식별정보 등 개인정보의 파기 범위는 별도로 확정한다.
- `POL-AUTH-033`: 별도의 ‘연결만 해제’ 기능은 초기 범위에서 제외한다. 사용자가 외부 서비스에서 직접 연결을 해제하는 경우에는 웹훅 등 제공자의 통지 방식으로 인지하고, 제공자·서비스 정책에 따라 인증과 연결 정보·기록을 처리한다. 외부 연결 해제의 세부 처리는 구현 전에 확정한다.

## 5. 미정 사항

- OAuth 시작·완료·계정 전환·로그아웃 API의 경로·응답·오류 코드와 현재 회원 인증 전달 방식
- 브라우저·WebView 환경별 리다이렉트·쿠키·CORS·CSRF 설정과 여러 탭의 인증 전환·토큰 갱신 조정 방식
- 앱에서 OAuth를 마친 뒤 WebView 인증으로 연결하는 완료 결과 전달 계약
- 사진의 복합 외래키와 기기 푸시 등록 등 기존 제약을 지키는 소유권·인증 세션 이전 방식
- 외부 서비스의 연결 해제 통지에 따른 인증 종료·회원 처리와 OAuth 식별정보 등 개인정보 파기 범위
- 장기 미접속 회원의 기록 보존·삭제 정책
