# 회원·인증 기능 명세

- 상태: 익명 인증 유지·OAuth 계정 연결 정책 / 수정일: 2026-11-03
- 관련 이슈: [#523](https://github.com/woowacourse-teams/2026-jachwi-sunbae/issues/523). OAuth 연결·기록 통합·다중 인증 세션·로그아웃은 구현 예정 정책이다.

## 1. 목적과 범위

PostHog에서 기존 로그인 화면 방문자의 85%가 이탈한 것을 확인해, 로그인 입력 없이 시작하는 익명 인증을 유지한다. 기록 보관과 기기 간 이용이 필요한 사용자는 카카오·Apple 계정을 선택적으로 연결한다.

회원은 서비스에서 발급한 ID로 기록을 소유하며, 이 ID는 사람이나 기기의 고유 ID를 뜻하지 않는다. 별도의 게스트 샘플 데이터는 제공하지 않는다.

현재 웹·WebView 인증을 확장한다. 서로 다른 OAuth 계정 간 기록 이전·병합, 한 회원에 여러 로그인 수단 추가, 기존 닉네임 회원의 기록 전환, 네이티브 앱의 업무 API 직접 호출은 범위에서 제외한다.

## 2. 요구사항

- `REQ-AUTH-001`: 앱을 시작할 때 입력 없이 인증을 시작한다. 회원이 없으면 익명 회원을 자동 생성한다.
- `REQ-AUTH-002`: 유효한 Refresh Token을 보관한 환경에서는 재방문해도 같은 회원의 기록을 이용한다.
- `REQ-AUTH-003`: Access Token이 만료되면 화면 상태를 유지한 채 새 토큰을 발급받아 이용을 계속한다.
- `REQ-AUTH-004`: 로그인 요청에서 기존 인증을 복원할 수 없으면 새 익명 회원으로 시작한다. 이전 회원의 데이터는 이 요청으로 삭제하지 않는다.
- `REQ-AUTH-005`: 토큰 갱신 요청에서 기존 인증을 복원할 수 없으면 실패를 알리고 새 회원을 자동 생성하지 않는다.
- `REQ-AUTH-006`: 익명·OAuth 회원 모두 인증된 상태에서 업무 API를 이용한다.
- `REQ-AUTH-007`: 회원은 다른 회원의 매물·체크 기록을 조회·변경·삭제할 수 없다.
- `REQ-AUTH-008`: DB 장애나 저장 데이터 손상을 인증 실패 또는 새 회원 생성으로 숨기지 않는다.
- `REQ-AUTH-009`: 회원은 탈퇴할 수 있다. 탈퇴하면 소유 기록을 논리 삭제하고 인증 정보를 폐기한다.
- `REQ-AUTH-010`: 회원은 마이 화면의 초기화로 지금 회원을 탈퇴 처리하고 새 익명 회원으로 다시 시작할 수 있다. 이전 회원의 기록에는 더 이상 접근할 수 없다.
- `REQ-AUTH-011`: 계정과 데이터를 완전히 지우는 것은 메일 요청으로 받는다. 요청하면 초기화 전 이전 회원의 데이터까지 파기한다.
- `REQ-AUTH-012`: 사용자는 익명 이용 중 카카오·Apple 계정을 선택적으로 연결한다.
- `REQ-AUTH-013`: OAuth 연결 후에도 현재 기록을 유지하며, 이미 연결된 회원이 있으면 그 회원의 기록과 함께 이용한다.
- `REQ-AUTH-014`: 같은 OAuth 계정으로 여러 기기에서 같은 회원의 기록을 이용한다.
- `REQ-AUTH-015`: 서로 다른 OAuth 계정은 별도 회원으로 관리하며, 계정 전환으로 기록을 자동 통합하지 않는다.
- `REQ-AUTH-016`: 로그아웃 후 새 익명 회원으로 이용하거나 같은 OAuth로 기존 회원을 복원할 수 있다.
- `REQ-AUTH-017`: OAuth 인증을 취소하거나 검증·통합에 실패하면 기존 회원과 기록을 유지하고, 실패를 새 회원 생성으로 숨기지 않는다.

## 3. 정책

### 3.1. 익명 회원과 기록

- `POL-AUTH-001`: 익명 회원 생성에는 서비스가 발급한 회원 ID를 사용한다. 닉네임·비밀번호 입력이나 기기 식별값은 사용하지 않는다.
- `POL-AUTH-002`: 유효한 Refresh Token이 정상 회원과 연결돼 있으면 같은 회원을 복원한다. 탈퇴한 회원은 복원하지 않는다.
- `POL-AUTH-003`: `POST /api/auth/login`의 Refresh Token이 없거나 만료·삭제됐거나 정상 회원과 연결되지 않으면 새 익명 회원을 생성한다. 이전 기록은 보존하되 OAuth 인증 전에는 새 회원에게 연결하지 않는다.
- `POL-AUTH-004`: 서로 다른 브라우저 프로필·앱에서 익명으로 처음 시작하면 각각 다른 회원이 된다.
- `POL-AUTH-005`: 회원 소유 데이터는 인증된 회원 ID를 기준으로 조회·변경·삭제 권한을 확인한다. 다른 회원의 자원은 `404`로 응답하고 노출하지 않는다.

### 3.2. 토큰과 API 접근

- `POL-AUTH-006`: Access Token은 15분간 유효한 JWT다. 지도·검색을 포함한 모든 업무 API에 `Authorization: Bearer <Access Token>`으로 전달한다. 인증 시작·복원·토큰 갱신·OAuth 인증 처리는 별도 인증 계약을 따른다.
- `POL-AUTH-007`: Refresh Token은 365일간 유효하며 서버에는 원문 대신 해시를 저장한다.
- `POL-AUTH-008`: 일반 인증 복원·토큰 갱신은 Refresh Token 값을 유지하고 만료를 요청 시점부터 365일로 연장한다. OAuth 인증 완료 시에는 `POL-AUTH-028`에 따라 교체한다.
- `POL-AUTH-009`: `POST /api/auth/refresh`는 기존 회원의 Access Token만 재발급한다. Refresh Token이 없거나 유효하지 않으면 `401 REFRESH_TOKEN_INVALID`를 반환하고 새 회원을 생성하지 않는다.
- `POL-AUTH-010`: 업무 API에 Access Token이 없거나 유효하지 않으면 `401 ACCESS_TOKEN_INVALID`를 반환한다. Access Token 만료 후 갱신에 성공하면 원래 요청을 한 번 재시도한다.
- `POL-AUTH-011`: 인증·OAuth 연결·통합 과정의 DB 장애 또는 저장 데이터 손상은 서버 오류로 처리한다.

### 3.3. 탈퇴·초기화와 데이터 삭제

- `POL-AUTH-012`: `DELETE /api/members/me`는 회원과 소유 기록을 논리 삭제하고 모든 Refresh Token을 폐기한다. 응답에서 Refresh 쿠키를 만료시키며 기존 Access Token은 회원 상태 검사로 거절한다.
- `POL-AUTH-013`: 탈퇴 시 날씨 알림을 비활성화하고 기기 푸시 토큰을 제거한다.
- `POL-AUTH-014`: 마이 화면의 초기화는 탈퇴 성공 후 `POST /api/auth/login`으로 새 익명 회원을 생성하고 인증·캐시를 전환한 뒤 홈으로 이동한다. 탈퇴 요청이 401이면 토큰을 한 번 갱신해 재시도한다.
- `POL-AUTH-015`: 탈퇴 요청이 실패하면 기존 회원과 인증 상태, 화면을 그대로 둔다. 탈퇴 뒤 로그인이 실패하면 이전 회원으로 되돌아가지 않고, 다음 요청의 자동 로그인이 새 회원을 만든다.
- `POL-AUTH-016`: 초기화로 논리 삭제된 이전 회원의 기록과 사진 파일은 초기화한 날부터 90일 동안 보관한 뒤 파기한다. 사용자가 앱에서 삭제한 매물, 체크리스트, 거리 메모도 삭제한 날부터 90일 뒤 같은 기준으로 파기한다.
- `POL-AUTH-017`: 메일로 계정과 데이터의 완전 삭제를 요청하면 지금 회원과 초기화 전 이전 회원의 데이터를 함께 파기한다.

### 3.4. OAuth 연결과 계정 전환

- `POL-AUTH-018`: OAuth 계정은 제공자와 검증된 사용자 식별값으로 구별한다. 서비스 회원과 OAuth 계정은 일대일로 연결하며 이메일·닉네임으로 동일 회원이라고 추정하지 않는다.
- `POL-AUTH-019`: 익명 회원이 OAuth를 연결할 때 연결된 회원이 없으면 현재 회원에 연결 정보만 추가한다. 연결된 회원이 있으면 그 회원을 기준 회원으로 정해 익명 기록을 통합한다.
- `POL-AUTH-020`: OAuth 회원이 같은 계정으로 인증하면 현재 회원을 사용한다. 다른 계정이면 기록 통합 없이 해당 계정의 회원으로 전환하고, 연결된 회원이 없으면 새 회원을 생성한다.
- `POL-AUTH-021`: 연결 전에 익명 기록이 선택한 OAuth 계정에 저장되며 다른 계정으로 이전할 수 없음을 안내한다.
- `POL-AUTH-022`: 카카오·Apple 인증 결과는 백엔드에서 검증한다. 카카오 토큰은 사용자 확인에만 사용하고 클라이언트에 전달하지 않는다. 카카오 Refresh Token의 장기 보관·주기적 갱신은 하지 않으며, 카카오 토큰 만료만으로 계정 연결이나 우리 인증을 종료하지 않는다.

### 3.5. 익명 기록 통합

- `POL-AUTH-023`: 매물·사진 메타데이터·사용자 체크리스트·거리 메모와 관련 기록의 소유권을 기준 회원으로 이전한다. 중복 제거 없이 ID·내용·삭제 상태와 기록 간 연결을 보존한다.
- `POL-AUTH-024`: 날씨 위치·알림 등 단일 설정은 기준 회원의 값을 우선한다. 해당 설정이 아예 없을 때만 익명 회원의 값을 가져오며, 알림 끄기 등 명시적 값은 덮어쓰지 않는다.
- `POL-AUTH-025`: 기록 이전·설정 반영·원래 익명 회원 비활성화·인증 전환은 한 트랜잭션으로 처리한다. 반복·동시 요청으로 중복 통합하지 않으며 탈퇴·초기화로 통합을 대신하지 않는다.
- `POL-AUTH-026`: 서버는 현재 익명 인증과 검증된 OAuth 결과로 통합 대상을 결정하고, OAuth 시작 요청과 완료 결과를 안전하게 연결한다.

### 3.6. 기기별 인증과 보관

- `POL-AUTH-027`: 한 회원에 여러 Refresh Token을 허용하고 브라우저 프로필·앱 설치별로 독립 발급한다.
- `POL-AUTH-028`: OAuth 인증 완료 시 현재 기기의 토큰을 선택된 회원의 새 Access Token·Refresh Token으로 교체한다. 통합 전 익명 회원의 인증은 모두 폐기하고 기존 JWT도 거절한다. 기준 회원의 다른 기기 인증은 유지한다.
- `POL-AUTH-029`: 회원 전환 시 이전 Access Token·회원별 캐시를 비우고 새 인증을 적용한다. 다른 탭에도 전환을 알리며 이전 회원 요청의 늦은 응답을 버린다.
- `POL-AUTH-030`: 웹·WebView는 Access Token을 웹 메모리에, Refresh Token을 HttpOnly·Secure 쿠키에 보관한다. 앱의 OAuth는 시스템 브라우저나 제공자 SDK를 사용하며 외부 브라우저와 쿠키를 공유한다고 가정하지 않는다. 일회용 완료 코드로 WebView 인증을 연결한다면 인증 요청에 연결하고 짧은 유효기간·일회 사용을 보장한다.

### 3.7. 로그아웃과 외부 계정 연결 해제

- `POL-AUTH-031`: 로그아웃은 현재 Refresh Token을 폐기하고 쿠키·클라이언트의 Access Token·캐시를 비운 뒤 새 익명 회원으로 시작한다. 기존 OAuth 연결·기록과 다른 기기 인증은 유지한다. 이미 발급한 Access Token의 세션별 즉시 차단은 지원하지 않으며 만료까지 최대 15분간 유효할 수 있다. 화면에서 기록을 삭제하는 초기화·탈퇴와 구분해 안내한다.
- `POL-AUTH-032`: OAuth 회원 탈퇴 시 외부 계정 연결도 해제한다. 제품 기록은 기존 삭제 정책을 따르며 OAuth 식별정보 등 개인정보의 파기 범위는 별도로 확정한다.
- `POL-AUTH-033`: 별도의 ‘연결만 해제’ 기능은 이번 범위에서 제외한다. 외부 서비스에서 직접 연결을 해제하면 검증된 웹훅 등으로 인지해 인증·연결 정보·기록을 처리한다. 세부 계약은 미정 사항에서 관리한다.

| AC-AUTH-006 | Access Token 없이 지도·검색·월세 등 업무 API를 호출한다.                  | `401 ACCESS_TOKEN_INVALID`를 받고, 유효한 Access Token을 첨부하면 해당 API를 이용할 수 있다.            |
| AC-AUTH-007 | 이용 중 Access Token이 만료된다.                                          | 갱신 후 실패한 요청을 한 번 재시도하며 화면·입력 내용은 유지된다.                                       |
| AC-AUTH-008 | 회원 A의 토큰으로 회원 B의 매물·체크 기록을 조회·변경한다.                | B의 내용이 노출되거나 변경되지 않는다.                                                                  |
| AC-AUTH-009 | 서로 다른 브라우저에서 처음 접속한다.                                     | 각각 다른 익명 회원으로 시작하며 기록을 공유하지 않는다.                                                |
| AC-AUTH-010 | 로그인·토큰 갱신 중 DB에 장애가 발생하거나 저장된 인증 데이터가 손상된다. | 서버 오류를 반환하며 이를 새 회원 생성이나 인증 실패로 처리하지 않는다.                                 |
| AC-AUTH-011 | 회원이 탈퇴한 뒤 기존 Access Token과 Refresh 쿠키로 요청한다.             | 소유 기록이 조회되지 않고, 기존 Access Token과 Refresh 쿠키 모두 인증에 사용할 수 없다.                 |

마이 화면의 초기화는 다음 기준으로 확인한다.

| ID          | 조건과 행동                                         | 관찰할 결과                                                                                          |
| ----------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| AC-AUTH-012 | 기록이 있는 회원이 마이 화면에서 초기화를 확인한다. | 새 익명 회원의 Access Token과 Refresh 쿠키를 받고 홈으로 이동하며, 이전 회원의 기록은 보이지 않는다. |
| AC-AUTH-013 | 초기화의 탈퇴 요청이 실패한다.                      | 실패 안내가 보이고 기존 회원과 기록을 그대로 이용할 수 있다.                                         |

OAuth 연결·통합과 기기별 이용은 다음 기준으로 확인한다.

| ID          | 조건과 행동                                                                                | 관찰할 결과                                                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| AC-AUTH-014 | 기록이 있는 익명 회원이 아직 서비스 회원에 연결되지 않은 OAuth 계정을 연결한다.            | 현재 회원 ID와 기록이 유지되고 새 인증 토큰이 발급된다.                                                                           |
| AC-AUTH-015 | 노트북 회원 10번에 연결된 카카오로 휴대폰의 익명 회원 20번이 인증한다.                     | 20번의 기록이 10번에 통합되고, 두 기기가 각자의 토큰으로 10번의 기록을 사용한다. 이후 기록도 10번에 저장된다.                     |
| AC-AUTH-016 | 같은 이름·주소·위치의 기록과 서로 다른 날씨·알림 설정을 가진 회원을 통합한다.              | 기록은 모두 유지되고 삭제된 기록이 복원되지 않는다. 기준 회원의 명시적 설정은 유지되며, 아예 없는 설정만 익명 회원에서 가져온다.  |
| AC-AUTH-017 | 기록 통합을 반복·동시 요청하거나 통합 중 DB 작업이 실패한다.                               | 중복 통합·일부 이전이 발생하지 않는다. 실패하면 이전 회원과 기록·인증을 유지하고 서버 오류를 반환한다.                            |

| AC-AUTH-020 | OAuth 인증을 취소하거나 검증에 실패한다.                                                   | 현재 회원·기록·인증을 유지하며 임의로 새 회원을 만들지 않는다.                                                                    |

## 5. 미정 사항

- OAuth 시작·완료·계정 전환·로그아웃 API의 경로·응답·오류 코드와 현재 회원 인증 전달 방식
- 브라우저·WebView 환경별 리다이렉트·쿠키·CORS·CSRF 설정과 여러 탭의 인증 전환·토큰 갱신 조정 방식
- 앱에서 OAuth를 마친 뒤 WebView 인증으로 연결하는 완료 결과 전달 계약
- 사진의 복합 외래키와 기기 푸시 등록 등 기존 제약을 지키는 소유권·인증 세션 이전 방식
- 외부 서비스의 연결 해제 통지에 따른 인증 종료·회원 처리와 OAuth 식별정보 등 개인정보 파기 범위
- 장기 미접속 회원의 기록 보존·삭제 정책
