# 생활권 탐색·상세 경로 MSW

2026-10-13 `develop`에 머지된 [탐색 PR #358](https://github.com/woowacourse-teams/2026-jachwi-sunbae/pull/358), [코드 응답 PR #359](https://github.com/woowacourse-teams/2026-jachwi-sunbae/pull/359), [경로 PR #360](https://github.com/woowacourse-teams/2026-jachwi-sunbae/pull/360)의 계약을 사용하는 로컬 시안입니다. 탐색과 상세 경로는 로그인 없이 요청합니다.

`npm run dev:mock`은 기존처럼 전체 MSW 시안입니다. `USE_REAL_COMMUTE_API=true npm run dev:mock`은 통근 조회만 MSW를 우회해 실제 API로 보내고 나머지 기능은 목 데이터를 유지합니다. `DEV_API_PROXY_TARGET`이 설정되어 있으면 개발 프록시로 전달합니다. 실제 통근 요청 실패 시 샘플로 자동 대체하지 않습니다. `npm run dev`에서는 모든 API를 실제 서버로 요청합니다.

확인 당시 dev 서버는 공개 통근 요청에도 `401 ACCESS_TOKEN_INVALID`를 반환했고, 이후 재검증에서는 프록시를 통한 요청도 HTML `503 Service Temporarily Unavailable`를 반환했습니다. 머지된 인증 제외 코드와 배포 상태를 확인해야 하며, 프론트에서 임의로 인증을 추가하거나 이를 성공으로 처리하지 않습니다. 서버 정상 응답을 이용한 결과 표시 검증은 아직 완료하지 못했습니다.

## 요청과 응답

### 초기 검증: 전국 원본 경계

현재 초기 검증은 `data/admin-dongs.geojson`에 저장한 사용자 제공 전국 원본을 그대로 사용합니다. 빌드가 기준일·SHA-256 내용 해시로 파일명을 생성하고 `boundaries/manifest.json`에 기록합니다. 원본 좌표·속성·Polygon·MultiPolygon·내부 링은 그대로 유지합니다. 원본은 3,559개 동, 28,652,853바이트이며 gzip 약 9.57MB입니다. 프론트 코드에는 해시 파일명이 없습니다.

시·도 분할 방식은 현재 사용하지 않습니다. 초기 검증에서는 제공받은 원본 경계를 그대로 배포합니다.

조회 버튼을 누르면 통근 요청과 manifest 조회를 동시에 시작합니다. manifest에서 파일명을 확인한 즉시 경계를 받으므로 서버 계산 결과를 기다리는 구조가 아닙니다. manifest는 조회마다 HTTP 재검증하며 경계는 React Query에 해시 파일명·주소 기준으로 캐시하고 30분간 미사용 캐시를 유지합니다. 초기 진입에는 다운로드하지 않습니다. 다운로드 실패 시 재시도할 수 있으며 파일에 없는 동네는 임의의 경계를 그리지 않고 위치 라벨과 누락 안내만 표시합니다. 원본의 첫 다운로드·파싱 비용은 실제 기기에서 검증해야 합니다.

`ADMIN_BOUNDARY_BASE_URL`에 CDN 경로를 설정할 수 있습니다. 기본값은 `/boundaries`로 로컬 정적 파일이며 빌드 시에도 파일을 복사하지만 초기 JS에 포함하거나 HTML에서 프리로드하지 않습니다. 실제 CDN 업로드는 하지 않았습니다. CDN에서는 JSON Content-Type, gzip/Brotli 압축, CORS와 `Cache-Control: public, max-age=31536000, immutable`을 설정하고 내용 변경 시 새 해시 URL을 사용합니다. CDN 캐시와 브라우저 HTTP 캐시는 React Query 캐시와 별도입니다.

원본 갱신 시 `data/admin-dongs.geojson`만 교체하고 빌드합니다. 빌드가 해시 파일·gzip 파일·manifest를 함께 생성하며 코드 상수 수정은 필요 없습니다. 배포는 gzip 내용을 `.geojson` URL로 먼저 올리고 `Content-Encoding: gzip`과 장기 캐시를 지정합니다. manifest는 마지막에 `no-cache`로 올리고 CloudFront 무효화 대상에 포함합니다. 오래된 해시 파일은 배포 sync에서 삭제하지 않습니다. 운영 사용 여부를 확인한 뒤 별도로 정리합니다. 서버와 CDN이 같은 기준일·SGIS 코드 체계를 쓰도록 협의해야 합니다.

프론트는 서버의 8자리 `adminDongCode`를 CDN 경계 파일의 코드와 결합하여 동 이름·중심좌표·경계를 표시합니다. 경계 파일에 없는 코드는 코드와 정류장 위치를 표시하고 누락 안내를 냅니다.

`GET /api/commute-areas/with-rents`는 모든 후보의 코드·시간·정류장 목록과 동네 월세 시세를 돌려줍니다(백엔드 #437). 시세 없는 예전 `GET /api/commute-areas`는 사용 중단이며 프론트는 더 이상 부르지 않습니다. 정류장의 `direction`은 서버가 더 쓰지 않아 늘 `null`로 오며(POL-COMMUTE-016), 목 응답도 같게 `null`로 둡니다. 경계는 별도 정적 파일로 한 번 받으며 행정동별 API 요청은 하지 않습니다.

| 파라미터     | 필수   | 기본값 | 범위               |
| ------------ | ------ | ------ | ------------------ |
| latitude     | 예     | 없음   | -90 이상 90 이하   |
| longitude    | 예     | 없음   | -180 이상 180 이하 |
| maxMinutes   | 아니오 | 60     | 정수 1~180         |
| maxTransfers | 아니오 | 2      | 정수 0~10          |

```text
/api/commute-areas/with-rents?latitude=37.5000776&longitude=127.0385419&maxMinutes=40&maxTransfers=1
```

성공은 `{ code: 'SUCCESS', message, data }`, 실패는 `{ code, message, errors }`입니다.
`data`에는 `maxMinutes`, `areaCount`, `rentStartDate`, `rentEndDate`, `areas`가 있습니다. 각 동은 `adminDongCode`, `commuteMinutes`, `monthlyRentKrw`, `depositKrw`, `transactionCount`, `legalDongNames`, `stations`를 포함합니다. 이름·중심좌표·경계는 CDN 파일에서 찾습니다.
시세는 관할 법정동 월세 거래를 합친 월세·보증금 중앙값이고 기간은 마지막 계약일부터 6개월입니다. 거래가 5건보다 적은 동네는 금액과 거래 수가 null이며 화면에서는 그 동네를 그리지 않습니다. 시세가 하나도 없으면 기간도 null입니다.
정류장은 `stopId`, `stopName`, `latitude`, `longitude`, `travelMinutes`, `direction`을 포함합니다. 방향은 문자열 또는 null입니다.
응답에는 기존 `destination`, `district`, `city`, `transferCount`, `departureStopName`이 없습니다. 환승 횟수는 추정해 표시하지 않습니다.

최대 환승 횟수는 사용자가 지정하는 요청 조건입니다. 응답에는 실제 경로별 환승 횟수가 없습니다.

동네 카드나 지도 지역을 누르면 `/neighborhoods/areas/:adminDongCode`(공개 탐색은 `/explore/areas/:adminDongCode`) 주소에서 지도 위 공용 `BottomSheet`로 상세를 표시합니다. 그 동네의 가장 빠른 출발 정류장, 또는 직접 고른 정류장의 `stopId`로 `GET /api/commute-areas/route`를 요청합니다. 목적지 좌표·최대 시간·최대 환승 횟수는 탐색 요청과 같은 값을 보냅니다. 응답의 `totalMinutes`, `transferCount`, `legs[]`에서 예상 시간, 버스·지하철·도보 구간, 노선명과 경유 정류장을 표시합니다. 손잡이를 드래그하거나 눌러 높이를 바꾸고, 내려서 닫거나 닫기 버튼·Escape로 지도에 돌아갈 수 있습니다. 지도 결과·선택·시점은 유지합니다. 실시간 도착 정보·요금·안내 시작 기능은 제공하지 않으며 지도에 노선 경로를 그리지 않습니다. 상세 주소로 직접 진입하여 탐색 결과가 없으면 지도 진입 버튼을 안내합니다.

## 실제 경계와 테스트 데이터

- 사용자 제공 `admin-dongs.geojson`에서 아래 세 동의 geometry만 추출했습니다. 기준일은 20250630입니다. 원본 전국 파일은 번들에 포함하지 않습니다.
- PR의 적재 정책처럼 경계 좌표를 소수점 다섯 자리로 제한했습니다. 서버의 약 15m 경계 단순화 품질·대용량 응답 성능을 재현하는 테스트는 아닙니다. Polygon·MultiPolygon과 내부 링을 보존하며 좌표는 [경도, 위도]입니다.
- API와 경계 파일 모두 SGIS 8자리 행정동 코드를 사용합니다. 행정동과 법정동 연결은 서버가 시세를 계산할 때 처리하므로 프론트는 법정동 코드를 다루지 않습니다.

| 이름                        | 행정동 코드 |
| --------------------------- | ----------- |
| 서울특별시 강남구 역삼1동   | 11230640    |
| 서울특별시 관악구 신림동    | 11210690    |
| 경기도 성남시 분당구 정자동 | 31023780    |

- 월세 시세는 역삼1동 68만원(42건), 신림동 45만원(18건, 신림동·봉천동)의 가상 값이고, 정자동은 거래가 적어 시세가 없는 경우를 보여줍니다.
- 통근 시간은 역삼1동 3분, 신림동 27분, 정자동 38분의 고정 샘플입니다. 실제 목적지 기반 길찾기가 아닙니다. 정자동 정류장 ID는 MSW 전용입니다.
- 시간·환승 조건에 맞는 정류장만 남기고, 동네 시간은 남은 정류장의 최솟값으로 계산합니다. 빈 동은 제외합니다. 동·정류장 모두 시간순입니다.
- 환승 필터 검증용 횟수는 MSW 내부에만 있습니다. 응답 필드는 추가하지 않습니다.
- 대기·환승·도착 정류장에서 목적지까지 도보가 포함된 시간으로 해석합니다. 집에서 출발 정류장까지의 도보나 실시간 교통은 계산하지 않습니다.
- 기본 지연은 800ms입니다. PR에서 공개 GET으로 허용하므로 프론트도 인증 토큰 없이 요청합니다.

## 화면과 테스트

결과 지도는 후보 중심이 화면 중앙보다 약 48px 위에 오도록 초기 중심을 조정합니다. 지역 선택 확대에서도 같은 간격을 적용하며 사용자가 지도를 이동할 때는 시점을 다시 강제하지 않습니다. 웹 하단 탭은 기존 높이(안전 영역 제외)의 약 2/3로 줄였습니다. 네이티브 탭의 자체 높이 설정은 변경하지 않습니다.

서버(`with-rents`)는 월세로 거르는 조건을 받지 않으므로, 월세 필터는 클라이언트에서 겁니다. 아래 시트의 ‘월세’ 칸(데스크탑은 결과가 나온 뒤 지도 왼쪽 아래에 띄우는 월세 슬라이더 카드 `RentSlider`)에서 전체 또는 30~~150만원 이하(10만원 단위)를 고르면, 받은 동네 시세(관할 법정동 월세 중앙값)가 그 이하인 동네만 남깁니다. 요청에는 싣지 않고, 결과에서 바꿔도 다시 조회하지 않습니다. 월세 조건 밖 동네는 랭킹과 동네 수에서 빼지만 지도에서는 지우지 않고 옅은 회색(`OUT_OF_RENT_COLOR`)으로 통근 색 동네 뒤에 깔아, 가깝지만 비싸서 빠진 동네를 보여 줍니다. 범례에는 `월세 조건 밖`을 덧붙이고, 회색 동네를 고르면 시세 아래에 `월세 조건(50만원 이하)보다 비싸요`를 적습니다. 거래가 적어 시세가 없는 동네는 회색으로도 그리지 않습니다. 시세가 없는 동네(관할 법정동 거래 5건 미만이라 서버가 금액을 `null`로 보낸 동네)는 클라이언트가 결과에서 빼 지도·카드에 그리지 않습니다. `useCommuteAreas`가 경계 파일을 고르기 전에 걸러, 그런 동네만 있는 시도의 경계 파일은 받지 않습니다. 조건에 맞는 동네가 없으면 월세 조건을 골랐을 때는 월세 조건을, 아니면 통근 시간이나 환승 조건을 넓혀보라고 안내합니다. 동네 카드에는 통근 시간과 함께 월세 시세를, 대중교통 상세에는 월세·보증금 중앙값과 거래 수·관할 법정동·거래 기간을 표시합니다.

고른 출퇴근 장소(위치 선택 중 후보와 결과의 목적지)는 거위 로고 핀 대신 `선택한 지역`이라고 적은 말풍선 핀(`MapMarker`의 `destination` 톤)으로 그리며(장소 이름은 검색창과 찾기 버튼에 있으니 핀에는 적지 않는다), 꼬리 끝이 좌표를 가리킵니다. 찾기 버튼은 지도 위에 두면 말풍선 핀과 겹쳐서, 휴대폰은 처음부터 아래에 떠 있는 시트(`이 조건으로 추천받아요` 제목, 통근, 환승, 월세 조건 칸, `{장소 이름}에서 찾기` 버튼, 이름을 모르면 `선택한 위치에서 찾기`)에 두고 위치를 고르기 전에는 버튼을 `지도에서 출퇴근 장소를 골라 주세요`로 막아 두며, 데스크탑은 왼쪽 조건 칸의 `이 조건으로 동네 찾기`에만 둡니다. 지역을 선택하면 해당 중심으로 이동해 동네 경계 전체가 340x300px 안에 들어가는 단계(`areaFocusLevel`)로 확대하며(작은 동네도 단계 5보다 가까이 가지 않고, 큰 동네도 마커가 보이는 단계 6.5보다 멀리 가지 않는다), 큰 요약 시트 대신 지도 좌표에 붙은 작은 정보 버튼(동네명·예상 통근 시간·월세 시세·대중교통 바로가기)을 표시합니다. 버튼을 누르면 별도 대중교통 상세 페이지로 이동합니다. 동네 찾기 지도는 SDK `morph`와 `easeOutCubic` 이동을 사용하며 이동 시간은 320ms로 요청합니다. 이동하는 동안 옆 칸이 열려 지도 크기가 바뀌면 크기 맞춤(`autoResize`)을 이동이 끝난 뒤로 미룹니다. 이동 도중에 맞추면 SDK가 이동을 그 자리에서 멈춰 목표 단계에 닿지 못하고, 정류장과 부동산 마커가 뜨지 않을 수 있기 때문입니다. SDK는 확대율 변경 시 자체 줌 애니메이션을 사용합니다. 동작 줄이기 설정에서는 즉시 이동합니다.

통근과 월세를 한 지도에서 함께 보므로 탐색 기준을 고르는 화면은 없습니다. 검색창 왼쪽 집 모양 버튼(결과 화면 왼쪽 위도 같다)은 들어온 화면으로 돌아가고, 주소로 바로 들어왔으면 홈(`/`)으로 갑니다.

첫 지도 진입 안내는 공용 `Toast`로 아래에서 위로 올라오며 8초 뒤 사라집니다. 위치를 선택하거나 필터를 열면 안내를 숨깁니다. ‘현재 위치에서 찾기’ 버튼은 표시하지 않으며 공용 현재 위치 아이콘으로 위치를 선택할 수 있습니다. 토스트는 지도 클릭을 막지 않고, 동작 줄이기 설정에서는 애니메이션을 생략합니다. `title`, `description`, `isOpen`, `onClose`, `duration`으로 다른 화면에서도 재사용할 수 있습니다.

통근 경계는 채움 불투명도 28%(선택 38%)와 얇은 색상 테두리로 표시합니다. 네온 외곽은 3px(선택 4px), 불투명도 12%로 번짐을 줄이고 파랑·초록·빨강의 구분을 강조합니다.

검색 결과는 최대 통근 시간과 상관없는 고정 구간으로 파랑(15분 이하)·초록(16~~30분)·빨강(31분 이상)을 구분합니다. 최대 시간이 짧으면 한두 색만 나오고, 범례도 선택한 최대 시간 안에 들어오는 구간만 표시합니다. 예를 들어 20분이면 15분 이하·16~~20분 두 구간입니다. 이는 프론트 표시 기준이며 API의 별도 순위·등급이 아닙니다. `model/commuteColors.ts`의 팔레트로 경계·채움·네온 외곽과 범례를 함께 바꿀 수 있습니다. 휴대폰 결과 상단은 한 줄로, 왼쪽에 들어온 곳(보통 홈)으로 나가는 뒤로가기(`동네 찾기 나가기`), 가운데에 조건 배지와 색상 범례, 오른쪽에 ‘다시 선택하기’를 둡니다. 통근과 환승 배지는 결과에서 바꿀 수 없어 회색으로 두고, 월세 배지만 눌러 바꿉니다. 배지는 줄을 넘기지 않습니다. 결과 지도에는 상위 1~~5위 동네 가운데에 순위 숫자와 동네 이름을 적은 순위 배지를 띄우고(1위는 노란색), 누르면 그 동네를 고릅니다. 가까이 확대했거나 휴대폰 동네 시트를 열었을 때는 거둡니다. 선택한 통근 동네는 요약 시트 대신 지도 정보 버튼으로 표시합니다. 새로고침·URL 직접 진입 시 검색 상태 복원은 후속 작업입니다.

일반 실행·재시도 버튼은 공용 `Button`을 사용합니다. 동네 카드와 상세 페이지의 정류장 목록은 마우스로 드래그해 가로 스크롤할 수 있고 스크롤바는 숨깁니다. 드래그 직후 클릭은 취소해 상세 이동·정류장 선택이 실수로 발생하지 않게 하며, 모바일 터치 스크롤과 키보드 선택은 유지합니다.

현재 위치 버튼은 지도 탭과 같은 `MapCurrentLocationButton`을 사용합니다. 위치 선택 중에는 현재 위치를 목적지로 선택하며, 검색 결과에서는 목적지·결과를 그대로 두고 지도 시점만 현재 위치로 이동합니다. 조회 중 중복 클릭을 막고 권한 거절·위치 조회 실패를 버튼 옆에서 안내합니다.

동네 카드는 공용 `RankedCard`를 사용합니다. `rank`(1~~5), `title`, `value`, `unit`, `description`, `selected`, `disabled`, `onSelect`를 전달하며 지도나 API를 알지 않습니다. 순위는 숫자 원 대신 `shared/assets/illustrations/rank-1~5.webp` 리본 메달 이미지로 표시하고(순위는 카드 이름으로 읽힌다), 배치·스크롤 폭은 페이지의 `className`으로 설정합니다. 상위 5개 동네 카드는 휴대폰·태블릿에서 공용 `HorizontalRail`에 넣어 가로로 넘기며, 마우스로 끌어서 넘기는 동작(`useHorizontalDrag`)도 레일이 맡습니다. 데스크탑(1024px 이상)에서는 레일 대신 지도 왼쪽 칸(`aside`)에 세로로 쌓고, 조건에 맞는 동네가 없다는 안내도 그 칸에 둡니다. 데스크탑과 휴대폰은 구도가 달라 `NeighborhoodPreviewPage`가 `useIsDesktop`으로 `desktop/NeighborhoodPreviewDesktopPage`와 `mobile/NeighborhoodPreviewMobilePage` 중 하나를 고릅니다. 검색 상태(`useNeighborhoodPreview`)는 고르는 쪽에서 한 번만 만들어 넘기므로 창 폭이 바뀌어도 결과가 유지됩니다. 지도 설정(`useNeighborhoodMapView`), 분석 오버레이, 검색창, 현재 위치 버튼은 두 화면이 함께 씁니다. 데스크탑 결과의 왼쪽 칸 위에는 `다시 선택하기`와 기준 요약(통근, 환승)을 두고(월세 선택은 두지 않는다), 지도 위에는 통근 시간 색상 기준만 남깁니다. 데스크탑은 랭킹 카드나 지도 위 동네를 고르면 경로를 바로 그리지 않고, 목록 옆 칸에 동네 이름과 월세·보증금(`월세 68만원 / 보증금 1,000만원`), 다방 링크, 그리고 휴대폰 시트처럼 `정류장`과 `공인중개사`로 나눈 목록을 엽니다(`AreaSummary`). 데스크탑은 분할 버튼 대신 밑줄 탭으로 나누고, 동네마다 정류장 탭에서 시작하며, 지도 마커도 탭에 맞춰 정류장만 또는 공인중개사만 올립니다. 공인중개사를 고르면 같은 칸에 그 정보를 엽니다. 랭킹 목록은 카드만 두어 길어지지 않습니다. 출발 정류장을 바꾼 지표(`commute_departure_station_changed`)는 이 목록에서 고를 때 남깁니다. 고른 카드를 다시 누르거나 옆 칸의 `동네 정보 닫기`를 누르면 동네 선택을 풉니다. 옆 칸이 통째로 넘어가므로 출발 정류장 목록은 높이를 묶지 않습니다. 출발 정류장을 고르면 같은 칸에 그 정류장의 경로를 열고, `정보 닫기`를 누르면 그 동네의 출발 정류장 목록으로 돌아갑니다. 출발 정류장을 고르면 지도를 그 정류장으로 지도 단계 3(`STATION_FOCUS_LEVEL`)까지 확대하고, 고른 정류장은 확대 단계와 상관없이 지도에 따로 찍습니다. 정보 칸 위의 `<` `>`(`N / M`)로 같은 동네의 앞뒤 출발 정류장으로 넘기며, 넘길 때마다 지도와 왼쪽 목록 선택도 함께 옮깁니다. 첫·마지막 정류장에서는 해당 쪽 버튼을 막습니다. 동네 대중교통 상세에는 출발 정류장 선택지를 두지 않고 첫 출발 정류장 기준 경로만 보여 줍니다. `다시 선택하기`는 열어 둔 정류장·부동산 정보도 닫습니다. 지도 위 `대중교통 정보 보기` 말풍선은 두지 않습니다. 출발 정류장을 고르면 같은 옆 칸에 그 정류장에서 출발하는 경로를 엽니다. 휴대폰은 동네를 고르면 지도 위 말풍선 대신 아래에 `정류장`·`공인중개사` 분할 탭 시트(`AreaPlacesSheet`)를 올립니다. 정류장 탭은 그 동네의 출발 정류장, 공인중개사 탭은 동네 단위로 받을 수 없어 지금 화면 범위의 공인중개사입니다. 시트 위쪽에는 월세·보증금 시세와 관할 법정동·거래 기간을 두고, 동네 이름 아래에는 전체 주소를(공용 `BottomSheet`의 `subtitle`), 제목 오른쪽 끝에는 다방 아이콘, 한 줄 `현재 지역의 매물은?`, 외부 링크 표시(네모에 화살표)가 든 작은 버튼(`ListingLink`의 `variant="icon"`, `BottomSheet`의 `headerEnd`)을 둡니다(휴대폰은 동네 대중교통 상세로 넘기는 버튼을 두지 않는다). 지도 마커도 탭에 맞춰, 정류장 탭에서는 정류장만, 공인중개사 탭에서는 공인중개사만 올리고 거리 메모는 숨깁니다. 항목을 고르면 그 자리로 지도 단계 3까지 확대하고 시트를 바꾸지 않은 채 그 안에서 정보(정류장은 경로, 공인중개사는 전화 걸기)로 넘어가며, 제목 왼쪽 뒤로가기로 목록에 돌아옵니다. 동네 없이 마커로 연 장소 시트도 뒤로가기로 닫습니다. 두 시트 모두 닫기(X) 버튼이 없고, 끌어 내리면 닫히며(동네 시트는 동네 선택을 푼다), 지도 빈 곳을 찍으면 닫지 않고 제목만 보이게 내립니다. 동네 시트가 열린 채 지도의 동네(고른 동네든 다른 동네든)를 찍으면 시트를 닫고 동네 선택을 풀어 랭킹을 다시 보여 주고, 동네를 고르지 않은 상태에서 찍으면 그 동네를 고릅니다. 끝까지 끌어 올리면 손잡이 없이 화면 전체를 덮는 페이지가 되고, 헤더의 `<`로 시트로 돌아오거나(정보를 보던 중이면 목록으로) `X`로 닫습니다. 대중교통 상세는 공용 `ListDetailLayout`(`shared/ui/list-detail-layout`)으로 목록 옆 칸에 붙여 열고, 닫기 버튼은 상세 칸 옆 지도 왼쪽 위에 둡니다. 상세를 보던 중 목록에서 다른 동네를 고르면 그 동네 상세로 바로 옮깁니다. `ListDetailLayout`은 목록·상세·본문 세 칸 배치만 맡아, 매물 목록·체크리스트처럼 같은 구도의 화면에서도 쓸 수 있습니다. 목록과 상세 칸은 고정 폭 대신 배치 폭의 28%를 최소와 최대 사이(목록 20~~24rem, 상세 22~~26rem)로 맞춰 좁은 데스크탑에서 함께 줄어들고, 지도 화면의 뼈대도 같은 배치를 씁니다. 데스크탑은 위치를 고르는 동안에도 왼쪽 칸을 두어 출퇴근 장소, 통근 시간과 환승 버튼, `이 조건으로 동네 찾기` 버튼을 펼쳐 두고(지도 위 칩·바텀시트·주소 후보는 이 칸으로 옮긴다), 지도는 위치를 찍는 데만 씁니다. 분석 중·실패 안내는 지도를 지우지 않고 반투명하게 덮습니다. Storybook의 `공용/RankedCard`에서 1~~5위, 선택·비활성 상태와 가격 표시 예시를 확인할 수 있습니다.

조건 선택 중에는 목적지를 다시 찍을 수 있습니다. 검색 결과 지도에서는 빈 곳을 눌러도 목적지·결과를 유지하고, ‘다시 선택하기’(휴대폰은 결과 상단 오른쪽)를 눌러야 위치 선택 화면으로 돌아갑니다. 이때 마지막 지도 중심·확대율을 유지하며, 새 조건으로 조회하면 새 결과에 맞춰 지도를 표시합니다. 결과 지도를 떠날 때 기억한 확대 단계와 화면 범위를 비워, 돌아온 지도가 멈추기 전에 이전 확대 단계의 정류장과 부동산 마커를 올리지 않습니다.

위치 미선택 상태에서는 지도 하단에 출퇴근·통학 목적지를 검색하거나 지도에서 선택하라는 짧은 안내를 표시합니다. 안내는 지도 클릭을 막지 않으며 위치를 선택하면 사라집니다. 선택 후 제목에는 위치 이름·주소를 표시하고 위도·경도 문자열과 위치 다시 선택 버튼은 표시하지 않습니다. 주소 조회 실패 시 일반 위치 이름으로 표시합니다.

첫 진입 `/neighborhoods`(공개 탐색은 `/explore`)에서 바로 지도를 엽니다. 휴대폰은 아래 시트의 통근, 환승, 월세 조건 칸으로 필터 시트를 열 수 있으며, 위치 선택만으로는 필터 시트를 열지 않습니다. 조건 칸은 위치를 고르기 전후로 자리를 옮기지 않습니다. 세 칸은 한 상자 안에 같은 폭으로 나란히 두고, 칸마다 위에 항목, 아래에 값을 적습니다. 현재 위치 버튼은 이 시트 위에 두고, 지도 누르기 안내는 본 방 기록과 같은 공용 지도 안내(`MapTapIntro`)로 지도를 살짝 어둡게 덮고 손가락이 누르는 움직임을 보여 줍니다. 이 시트는 공용 바텀시트처럼 태블릿(1023px까지)도 화면 폭을 채웁니다. 기준을 고르던 예전 주소(`/explore/commute`, `/explore/price`, `/neighborhoods/map?mode=…`)는 새 주소로 보내며, 통근 동네 상세 주소는 이어 주고 법정동 월세 상세 주소는 지도로 보냅니다. 위치 권한이 이미 허용돼 있으면 지도만 현재 위치로 옮기며(현재 위치는 마커로 그리지 않는다), 미허용·조회 실패 시 권한 창이나 키보드를 자동으로 띄우지 않습니다.

통근 시간·환승 필터는 공용 바텀시트에 배치합니다. 위치를 선택하면 해당 위치로 확대하고 마커 옆 조회 버튼을 표시합니다. 버튼은 지도 좌표에 고정되어 지도를 옮겨도 마커를 따라갑니다. 필터 시트를 닫아도 선택 위치는 유지합니다. 경계와 하단 카드로 선택한 동네만 확대하고 정보 버튼을 표시합니다. 대중교통 상세는 별도 페이지로 이동하며 X로 지도 정보 버튼에 돌아옵니다.

통근, 환승, 월세 조건 칸을 누르면 해당 항목만 공용 바텀시트에서 편집합니다. 칸의 항목 이름 옆에는 아래 화살표를 둡니다. 필터 시트는 공용 `BottomSheet`의 `resizable={false}` 옵션으로 손잡이를 숨기고 높이를 고정합니다. 닫기·Escape로 취소하거나 적용 버튼으로 완료합니다. 다른 시트는 끌어서 높이를 바꿉니다. 공용 `BottomSheet`는 손잡이를 누르기만 해서는 높이를 바꾸지 않고(잘못 눌러 시트가 오르내리지 않게), 끌거나 키보드 위·아래 화살표로만 바꿉니다. 끝까지 올리면 헤더에 뒤로가기·닫기가 있는 페이지가 됩니다(`fullPage`, 기본으로 켜고 페이지로 열면 안 되는 화면만 `fullPage={false}`로 끕니다). 페이지는 시트가 든 칸이 아니라 화면 전체를 덮어, 저렴한 한 끼처럼 시트 위에 머리와 탭이 있는 화면도 맨 위까지 올라갑니다. 태블릿(768~~1023px)은 휴대폰처럼 화면 폭을 채우고, 데스크탑(1024px부터)만 30rem 폭으로 가운데에 띄웁니다. 끄는 동안은 시작할 때 한 번만 최대 높이로 늘린 뒤 `transform`으로 움직여, 움직일 때마다 시트 안을 다시 배치하고 그리지 않습니다. 시트는 `peekSignal`이 바뀌면 제목만 보이게 내리며, `onBack`을 주면 제목 왼쪽에 뒤로가기를 둡니다. 통근 시간은 공용 `WheelPicker`로 10·20·30·40·50·60분을 고르고, 환승은 0·1·2회 버튼으로 선택합니다. ‘적용’을 눌러야 조건이 반영되며 취소하면 기존 값이 유지됩니다. 휠은 스크롤·터치와 방향키·Home·End를 지원합니다. 이는 UI 범위이며 서버 계약 자체의 허용 범위(시간 1~~180, 환승 0~~10)는 변경하지 않습니다. 데스크탑 왼쪽 조건 칸의 통근 시간과 환승 횟수는 공용 `SegmentedControl`로, 결과 지도 위 월세는 공용 `Slider`로 고릅니다. 공용 `WheelPicker`, `SegmentedControl`, `Slider`의 속성 이름은 [SEED Design](https://seed-design.io/components) React 컴포넌트를 따릅니다(`value`와 `onValueChange`, `values`와 `onValuesChange`, `label`, `indicator`, `description`, `markers`, `size`, `aria-label`). 패키지는 들이지 않고 이름만 맞춘 자체 구현입니다.

`npm run dev:mock`의 `/neighborhoods`에서 위치·시간·최대 환승을 확정하면 조회합니다. 분석 로딩 이후 전체 후보 경계를 표시하고, 통근 시간이 짧은 상위 5개 동네를 하단 가로 카드로 보여줍니다. 카드나 지도에서 동네를 선택하면 경계 강조와 정류장 목록·상세 대중교통 경로를 표시합니다. 닫아도 경계는 유지합니다. MSW 노선·시간은 실제 이동 경로가 아닌 샘플입니다.

로그인 뒤 화면은 바텀탭 없이 엽니다. 동네 찾기는 홈의 `동네 찾기` 카드에서 `/neighborhoods`로 이동합니다. 네이티브 탭바를 지원하는 앱에도 탭바를 숨기라고 알리며, 탭바 자리 여백은 두지 않습니다.

import { createCommuteAreaHandlers } from '@/app/mocks/handlers/commuteAreaHandlers';

server.use(...createCommuteAreaHandlers({ scenario: 'empty', delayMs: 0 }));

결과 지도에서 동네를 고르거나 가까이 확대하면(지도 단계 6.5 이하, 축척 200~~300m 정도. 한 번 올린 마커는 단계 7을 넘어야 거두는데, 데스크탑 휠은 한 칸에 0.15단계씩 소수로 멈춰 올리고 거두는 기준이 같으면 경계를 오갈 때마다 마커가 깜빡이기 때문이다) 지금 화면 안의 버스정류장(`GET /api/maps/bus-stops`)과 공인중개사(`GET /api/maps/agencies`)를 함께 조회해 카테고리 마커로 올립니다(`useNeighborhoodPlaces`, `useViewportPlaces`). 화면 가운데를 중심으로 모서리까지 덮는 가장 작은 반경(500·1000·2000m)을 고르고(`mapViewportQuery`), 받은 결과 중 화면 안의 것만 남깁니다. 서버 반경은 최대 2km라, 화면이 그보다 넓으면 버스정류장은 화면을 네 칸으로 나눠(`viewportTiles`) 칸마다 조회해 합칩니다. 지도를 옮기는 동안에는 새 결과가 올 때까지 이전 마커를 그대로 둡니다. 지도 이동이 끝날 때마다 다시 조회하며 같은 화면은 5분 동안 캐시를 씁니다. 동네를 고르지 않고 멀리 보면 마커를 내리고 색상 기준 아래에 `동네를 고르거나 가까이 확대하면 정류장·부동산이 보여요`를 띄웁니다. 정류장·부동산은 따로 목록이나 탭을 두지 않고 지도 마커로만 엽니다. 왼쪽 칸은 동네 랭킹만 둡니다. 데스크탑은 마커를 누르면 그 정보를 랭킹 옆 칸(`NeighborhoodPlacePanel`)에 바로 엽니다. 정류장은 그 정류장에서 목적지까지의 경로(`RouteGuide`, 동네 상세와 같은 타임라인)를, 부동산은 전화번호와 `번호 복사`(데스크탑에서는 `tel:` 링크가 동작하지 않는 일이 많다)·카카오맵을 보여 주며, 닫으면 보던 동네 상세로 돌아갑니다. 랭킹 카드나 지도 위 동네를 고르면 장소 정보는 닫습니다. 휴대폰은 같은 내용(`PlaceDetails`)을 높이가 고정된 공용 `BottomSheet`(`NeighborhoodPlaceSheet`)로 아래에 띄웁니다. 정류장은 전체 화면으로 넘기지 않고 바텀시트(처음 55%, 끌어 올리거나 내릴 수 있음) 안에서 목적지까지 경로를 바로 보여 주며, 부동산은 시트에서 바로 `전화 걸기`(`tel:`)와 카카오맵을 보여 줍니다. 다른 마커를 고르면 시트 내용만 바뀝니다. 휴대폰은 정류장·부동산 정보를 띄우는 동안 동네 시트 자리에 장소 시트를 띄우고, 정보를 닫으면 동네 시트로 돌아옵니다. 동네를 고르면 휴대폰 시트와 데스크탑 요약에 시세와 출발 정류장 목록만 두고(공인중개사 탭은 없다), 지도에도 정류장 마커만 올립니다. 공인중개사는 동네를 고르지 않고 가까이 확대했을 때 지도 마커로 봅니다. 상위 동네를 고르면 동네 경계, 첫 출발 정류장, 출퇴근 장소가 모두 들어오게, 출발 정류장을 고르면 그 정류장부터 출퇴근 장소까지 경로 전체가 들어오게 지도를 옮깁니다(`routeFocusView`, 5~~10단계). 경로가 길면 마커를 올리는 단계보다 멀리 보므로 정류장·부동산은 더 다가가야 보입니다. 새로고침·뒤로가기로 고른 동네가 복원되면 전체 보기 대신 같은 경로 시점으로 엽니다. 결과 지도에는 현재 위치 버튼 위에 확대(+)·축소(-) 버튼(`MapZoomControl`)을 두며, 휠이나 손가락으로 바꾼 단계에서 한 단계씩 옮깁니다. 휴대폰과 태블릿에서 동네 시트나 장소 시트를 띄우면 두 버튼을 시트 바로 위(`BottomSheet`의 `floating`)에 붙여 시트와 함께 오르내리게 하고, 페이지로 열면 숨깁니다. 고른 출발 정류장 마커는 누를 수 있는 마커로 두어, 눌러도 지도 빈 곳 누르기로 넘어가 열어 둔 경로를 닫지 않습니다. 데스크탑에서 옆 칸이 열리고 닫혀 지도 칸 폭이 바뀐 채로 시점을 옮기면, 옮기기 전에 지도 크기를 맞추고(`autoResize`) 한 번만 옮깁니다. 옮기는 도중에 오는 idle은 중간 시점으로 보고 화면에 알리지 않아, 화면이 중간 시점으로 다시 옮기며 튀지 않게 합니다. 거리 메모는 본 방 기록 지도에서만 보고, 동네 찾기 결과 지도에는 조회하거나 올리지 않습니다. 지도에서 내린 마커는 지도 레이어(`mapMarkerLayer`)가 들고 있다가 같은 모양으로 다시 요청되면 새로 만들지 않고 다시 붙이며, 요청에 없는 마커는 언제나 지도에서 내립니다. 멀리 볼 때는 지도가 멈춰도(idle) 화면 범위를 상태로 올리지 않아 동네 찾기 화면을 다시 그리지 않습니다. 주변 정류장 API의 정류장 ID(`GGB206000683`)는 경로 API 형식(`BS_TAGO_GGB206000683`)으로 바꿔 조회하며(`transitStopIdForBusStop`), 경로망에 없는 정류장이면 `선택한 정류장을 찾지 못했어요`를 보여 줍니다. 경로 MSW는 고정 좌표 정류장에서 출발하는 경로도 거리로 어림해 돌려줍니다. 그래서 동네 상세의 `정류장·공인중개사 보기` 카드는 없앴습니다. 버스정류장·중개업소 MSW(`mapHandlers`의 `*/api/maps/bus-stops`, `*/api/maps/agencies`)는 `fixtures/placeFixtures`의 정해진 좌표(서울시청, 판교, 역삼1동, 신림동, 정자동 주변)에서 조회 반경 안에 든 것만 가까운 순으로 돌려줍니다. 요청 중심을 기준으로 흩어 놓으면 지도를 옮길 때 마커가 화면을 따라와 실제와 달라 보이기 때문입니다. 서울시청 주변의 `demo-agency-1`, `demo-agency-2`는 백엔드 demo 공급자와 같은 연락처를 쓰며, 좌표·반경이 잘못되면 `MAP_QUERY_INVALID` 400으로 응답합니다. 통근 응답의 출발 정류장은 서울·경기 버스정보시스템이 같은 정류장을 기관 코드만 다르게(`BS_TAGO_SEB…`, `BS_TAGO_GGB…`) 두 번 내려주므로, 기관 코드를 뺀 정류소 ID가 같으면 통근 시간이 짧은 하나만 남깁니다(주변 버스정류장 API #407과 같은 규칙).

검증은 시나리오보다 먼저 실행합니다. 실제 API에 테스트용 파라미터는 추가하지 않습니다. 테스트에서는 범위·기본값·정렬·실제 경계·MultiPolygon·오류·빈 결과·취소·선택 후 경계 유지 등을 검증합니다.
