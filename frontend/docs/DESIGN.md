# 매물 체크리스트 UI

## 기준

사용자가 확인한 시안을 기준으로 모바일 앱의 웹 화면, 매물 상세 탭, 데스크탑 상세 패널과 체크리스트 전용 화면이 같은 컴포넌트를 사용한다. 기존 디자인 토큰과 공용 UI를 재사용한다.

## 색상과 표면

`tokens.styles.ts`의 `--color-surface`, `--color-ink`, `--color-muted`, `--color-border`를 사용한다. 평가 선택은 `--color-check-good-ink`, `--color-check-caution-ink`와 같은 색의 옅은 바탕으로 표시한다. 항목 전체를 하나의 중립색 테두리와 `--radius-md`로 묶고 카테고리는 구분선으로 나눈다.

## 글자와 간격

제목은 1.05rem, 카테고리는 0.9375rem, 질문은 0.875rem, 메모는 0.8125rem을 사용한다. 터치 기기의 메모 입력은 확대를 방지하도록 1rem으로 표시한다. 묶음 안쪽 여백은 `--space-md`, 항목 위아래 여백은 `--space-md`, 질문과 버튼 간격은 `--space-sm`을 사용한다.

## 구성과 반응형

상단 집계 링은 기존 `ChecklistProgressRing`을 유지한다. 항목 묶음 안쪽 상단에 ‘사용자 체크리스트’와 전체 평가 수를 `0/12` 형식으로 표시한다. 카테고리별 개수는 표시하지 않는다. 분류 순서는 보안, 창문·채광, 수도·화장실, 방 상태, 기본 옵션이다. API의 `category`를 보존해 그룹을 구성하며 `OTHER`는 기타에 표시한다. 카테고리가 없는 이전 API 응답에만 기존 제공 항목 ID 매핑을 적용한다. 실제 항목 수와 질문은 API 응답을 유지한다. 계약 전 항목은 계약 전 확인으로 묶는다.

질문과 회색 메모 입력은 왼쪽, 괜찮음·주의 버튼은 오른쪽에 배치한다. 질문은 줄바꿈하며 버튼은 줄어들지 않는다. 320px 화면과 데스크탑 패널에서 동일한 구조를 사용한다.

## 공용 컴포넌트와 상태

- `PropertyChecklist`: 제목, 전체 평가 수, 카테고리, 항목을 조립하는 도메인 공용 UI.
- `PropertyChecklistItemControl`: 평가와 메모 저장을 연결하는 도메인 공용 UI.
- `Button`: 평가·재시도에 사용하는 기존 공용 버튼. 선택 상태는 `aria-pressed`와 체크 표시로 구분한다.
- `TextAreaField`: `inline` 변형은 테두리 없는 회색 입력과 접근 가능한 숨김 라벨을 제공한다. 기본·입력·저장 중·저장 실패 상태를 지원한다.

메모는 항상 질문 바로 아래에서 입력하며 입력칸을 벗어나면 저장한다. 저장 중에는 읽기 전용으로 두어 연속 요청을 막고, 실패하면 입력 내용을 유지하고 다시 저장할 수 있게 한다. 입력칸의 Escape는 저장 전 내용으로 되돌린다. 평가를 다시 누르면 미확인으로 돌아간다.

## 접근성과 동작

평가 버튼은 저장 중 포커스를 유지하고 전체 평가 수는 문장으로 알린다. 모든 입력은 라벨과 포커스 표시를 가진다. 터치 버튼은 최소 44px 높이를 확보한다. 새로운 애니메이션은 추가하지 않는다.

## 적용 범위

앱 셸은 같은 웹 프론트엔드를 표시하므로 별도의 네이티브 화면을 추가하지 않는다. 새로운 카테고리나 질문을 백엔드에 생성하지 않으며, 신규 제공 항목은 ID와 무관하게 서버의 카테고리로 분류한다.

## 체크리스트 편집과 항목 추가

편집 본문은 ‘추가된 체크리스트’와 전체 항목 수를 표시하고, 같은 카테고리 순서와 SVG 아이콘으로 나눈다. 기존 `ChecklistItemRow`로 카테고리 안에서 순서 변경과 삭제를 제공한다. 항목 추가는 카테고리별 필터와 검색을 조합하며, 필터를 바꾸어도 선택을 유지한다. 이미 저장된 항목은 선택된 비활성 상태로 표시한다.

앱과 데스크탑은 같은 편집·추가 컴포넌트를 사용한다. `AddItemAction`의 작은 변형과 `Button`, `SearchField`, `SegmentedControl`, `BottomActionArea`를 재사용한다. 편집의 우측 ‘항목 추가’와 전체 폭 ‘체크리스트 저장’, 추가 화면의 선택 수·취소·추가는 화면 하단에 고정한다. 고정 영역은 본문 열 너비에 맞추고 안전 영역과 본문 아래 여백을 확보해 마지막 항목과 겹치지 않는다. 필터는 줄바꿈하며 터치 영역과 키보드 포커스를 유지한다.

매물의 ‘사용자 체크리스트’ 제목 옆에는 작은 순환 화살표 두 개와 ‘교체’ 링크를 둔다. 전체 평가 수는 우측에 유지한다. 교체는 기존 매물 체크리스트 선택 화면으로 연결하며, 기본 목록과 저장된 사용자 목록을 고를 수 있고 사용자 목록 묶음의 ‘만들기’에서 신규 생성 화면을 연다. 항목 추가 카드의 선택 원과 텍스트는 카드 높이에 대해 수직 중앙에 정렬한다.

## 체크리스트 관리 진입

홈·헤더의 체크리스트 메뉴는 관리 목록을 먼저 연다. 저장된 번들은 모두 이름과 항목 수로 표시하며 ‘사용자 체크리스트 만들기’를 제공한다. 모바일은 관리 → 생성 또는 편집 → 항목 추가 순서로 이동하고 저장·닫기는 관리로 돌아온다. 데스크탑은 가운데 관리 열을 먼저 보여주고 선택 시 공용 `SidePanelLayout`으로 목록 오른쪽에 편집 패널을 연다. 목록 선택 상태는 옅은 바탕과 체크 표시로 구분한다. 패널 안에서 스크롤하며 하단 동작은 패널 바닥에 고정한다. 기존 공용 버튼·아이콘·편집·추가 화면을 재사용한다.

체크리스트 교체 화면은 카드 선택만으로 이동하거나 적용하지 않는다. 하단 확인 버튼은 항상 고정 표시하며 선택 전·요청 중에만 비활성화한다. 현재 적용 중인 목록은 선택 상태와 별개로 ‘현재’ 배지를 표시하고, 기본 목록의 ‘추천’ 배지는 사용하지 않는다. 사용자 목록의 ‘만들기’는 생성 화면으로 바로 연결한다.

생성과 편집은 같은 공용 항목 폼을 사용하되 상단 제목으로 구별한다. 신규 생성과 로딩은 ‘체크리스트 만들기’, 기존 목록 수정은 ‘체크리스트 편집’으로 표시한다.

체크리스트 교체 확인 후에는 독립 체크리스트 페이지 대신 매물 상세의 체크리스트 탭으로 돌아간다. 신규 생성은 기본 CORE 항목 없이 전체 카탈로그에서 직접 선택하는 화면부터 시작한다. 매물 교체 화면에서 생성한 경우 매물 ID를 생성 URL에 보존하고, 저장 후 원래 교체 화면에서 새 번들을 선택한 상태로 보여 준다. 일반 관리 화면에서 생성하면 관리 목록으로 돌아간다.

## 매물 상세 입력과 메뉴

탭 쿼리 없는 매물 상세 진입은 정보 탭으로 시작하며 이전 탭을 저장하지 않는다. 교체 완료처럼 체크리스트 탭을 명시한 이동은 유지한다. 보증금·월세 입력은 저장된 값을 사용하고 미입력 금액은 0으로 표시한다. 내부 버튼·라벨 클릭은 편집 범위 안의 상호작용으로 유지하고, 범위 밖 클릭 또는 키보드 포커스 이동으로 저장·닫는다. 공용 더보기 메뉴도 범위 밖에서 상호작용하면 닫힌다.

체크리스트 항목 평가·메모 저장이 성공하면 해당 항목 캐시를 반영하고 상세 집계와 매물 목록을 함께 갱신한다. 목록이 열려 있으면 서버 진행률을 다시 받아 표시하고, 닫혀 있으면 다음 진입 때 최신 진행률을 받는다. 저장 실패 시 집계는 변경하지 않는다.

데스크탑 매물의 체크리스트 교체 화면은 기록 화면의 상세 열 안에서 연다. 동일한 교체 컴포넌트를 사용하되 본문과 확인 버튼은 해당 패널 폭·높이 안에 배치하며, 목록과 지도는 유지한다. 모바일은 기존 교체 페이지 이동을 유지한다. 매물 이름은 상단 헤더와 기본 정보의 수정 줄에서 표시하고 사진 아래 별도 이름 행은 제거한다. 더보기 메뉴는 상단 헤더 오른쪽에 배치한다.

홈 최근 기록과 매물 지도 말풍선은 공용 금액 요약을 사용한다. 보증금·월세가 모두 0인 미입력 매물은 `월세 0/0`으로 표시하며, 금액이 기록된 매물은 최신 공용 가격 컴포넌트의 월세 표기를 사용한다.

## 기본 이미지와 목록 관리

사진 없는 매물 상세에서만 첨부된 파란 지붕 집 이미지를 기본 이미지로 사용하며, 왼쪽 목록과 비교 화면의 오리 이미지는 유지한다. 실제 대표 사진이 있으면 우선 표시하며, 기본 이미지는 사용자 사진 수에 포함하지 않는다. 홈 한 끼 카드 오른쪽에는 제공된 오리 이미지를 공용 ActionCard 그림으로 배치하고 오류 화면에는 제공된 경고 오리를 사용한다. 동네 검색 결과는 검색창 바로 아래에 표시하고 지도 확대·축소와 현재 위치는 위쪽에 둔다. 매물 목록의 준비 중 필터와 일괄 삭제 모드는 제거하고 각 카드의 더보기 메뉴에서 삭제한다. 주소 없는 기록은 동네 배지를 만들지 않는다. 체크리스트 생성·편집에는 이름 입력, 기존 편집에는 삭제 확인을 제공한다. 방 비교 진행률은 단계 이름 없이 적용된 항목의 완료 수/전체 수로 합산한다.

첨부 이미지의 WebP 일반·2배 해상도 파일은 `techcourse-project-2026/jachwi-sunbae/web/assets/`에 업로드했다. 공개 버킷 설정 변경 없이 기존 CloudFront 경로로 제공하며, 소스 이미지도 저장소에 포함해 다음 dev·prod 빌드에서 같은 파일을 배포한다.

## 처음 방문한 사용자의 예시 매물

- 서버에서 받은 매물 목록이 비어 있으면 프론트에서만 `코엑스 근처` 예시 매물을 표시한다. 예시 데이터는 백엔드에 생성하거나 저장하지 않는다.
- 보증금 3,000만원, 월세 55만원, 관리비 15만원이며 수도세·전기세와 냉장고·전자레인지·책상 옵션을 포함한다. 체크리스트에는 무작위 예시 평가가 들어간다.
- 일반 매물의 공용 상세·사진·체크리스트 화면을 사용하며, 예시 수정은 메모리에 반영한다. 새로고침하면 예시 수정 사항은 초기화된다.
- 실제 매물 등록에 성공하거나 기존 매물이 조회되면 예시를 숨긴다. 등록 실패 시에는 유지한다. 숨김 여부는 API 주소와 회원 ID별로 브라우저에 보관하므로 실제 매물을 모두 삭제해도 같은 브라우저에서 다시 나타나지 않는다.
- 예시 삭제도 프론트에서만 처리한다. 예시 사진은 최적화한 WebP 파일로 제공하고, 추가한 사진은 브라우저 안에서만 사용한다.

## 동네찾기에서 홈으로 이동

동네찾기 헤더의 집 아이콘은 이전 방문 기록 대신 홈 주소로 직접 이동한다. 동네 선택과 상세 보기로 내부 주소 이력이 쌓여도 동일하게 동작하며, 모바일의 장소 검색·탐색 결과와 공개 탐색에서도 같은 동작을 사용한다. 데스크탑 공용 헤더의 홈 로고 역시 홈 링크를 사용한다.
