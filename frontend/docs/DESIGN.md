# 매물 체크리스트 UI

## 기준

사용자가 확인한 시안을 기준으로 모바일 앱의 웹 화면, 매물 상세 탭, 데스크탑 상세 패널과 체크리스트 전용 화면이 같은 컴포넌트를 사용한다. 기존 디자인 토큰과 공용 UI를 재사용한다.

## 색상과 표면

`tokens.styles.ts`의 `--color-surface`, `--color-ink`, `--color-muted`, `--color-border`를 사용한다. 평가 선택은 `--color-check-good-ink`, `--color-check-caution-ink`와 같은 색의 옅은 바탕으로 표시한다. 항목 전체를 하나의 중립색 테두리와 `--radius-md`로 묶고 카테고리는 구분선으로 나눈다.

## 글자와 간격

제목은 1.05rem, 카테고리는 0.9375rem, 질문은 0.875rem, 메모는 0.8125rem을 사용한다. 터치 기기의 메모 입력은 확대를 방지하도록 1rem으로 표시한다. 묶음 안쪽 여백은 `--space-md`, 항목 위아래 여백은 `--space-md`, 질문과 버튼 간격은 `--space-sm`을 사용한다.

## 구성과 반응형

상단 집계 링은 기존 `ChecklistProgressRing`을 유지한다. 항목 묶음 안쪽 상단에 ‘사용자 체크리스트’와 전체 평가 수를 `0/12` 형식으로 표시한다. 카테고리별 개수는 표시하지 않는다. 분류 순서는 보안, 창문·채광, 수도·화장실, 방 상태, 기본 옵션이다. API에는 카테고리가 없으므로 현장 제공 항목 ID를 기준으로 분류하며 미분류 항목은 기타에 표시한다. 실제 항목 수와 질문은 API 응답을 유지한다. 계약 전 항목은 계약 전 확인으로 묶는다.

질문과 회색 메모 입력은 왼쪽, 괜찮음·주의 버튼은 오른쪽에 배치한다. 질문은 줄바꿈하며 버튼은 줄어들지 않는다. 320px 화면과 데스크탑 패널에서 동일한 구조를 사용한다.

## 공용 컴포넌트와 상태

- `PropertyChecklist`: 제목, 전체 평가 수, 카테고리, 항목을 조립하는 도메인 공용 UI.
- `PropertyChecklistItemControl`: 평가와 메모 저장을 연결하는 도메인 공용 UI.
- `Button`: 평가·재시도에 사용하는 기존 공용 버튼. 선택 상태는 `aria-pressed`와 체크 표시로 구분한다.
- `TextAreaField`: `inline` 변형은 테두리 없는 회색 입력과 접근 가능한 숨김 라벨을 제공한다. 기본·입력·저장 중·저장 실패 상태를 지원한다.

메모는 항상 질문 바로 아래에서 입력하며 입력칸을 벗어나면 저장한다. 저장 중에는 읽기 전용으로 두어 연속 요청을 막고, 실패하면 입력 내용을 유지하고 다시 저장할 수 있게 한다. 입력칸의 Escape는 저장 전 내용으로 되돌린다. 평가를 다시 누르면 미확인으로 돌아간다.

## 접근성과 동작

평가 버튼은 저장 중 포커스를 유지하고 전체 평가 수는 문장으로 알린다. 모든 입력은 라벨과 포커스 표시를 가진다. 터치 버튼은 최소 44px 높이를 확보한다. 새로운 애니메이션은 추가하지 않는다.

## 적용 범위

앱 셸은 같은 웹 프론트엔드를 표시하므로 별도의 네이티브 화면을 추가하지 않는다. 새로운 카테고리나 질문을 백엔드에 생성하지 않으며, 카테고리 API가 추가되면 ID 매핑을 해당 응답으로 교체한다.
